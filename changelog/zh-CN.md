# 更新日志

FinStats 的所有变更，最新的在前。本文件编译进程序，应用中的**更新日志**标签页显示的就是它。

格式：`## [version] - date`，历时数天完成的版本写作 `## [version] - first day to release day`，随后是
`### Added`、`### Changed`、`### Security`、`### Performance`、`### Stability`、`### Fixed` 或 `### Removed`
（新增、变更、安全、性能、稳定性、修复、移除），每项变更一条。安全指可能被人滥用的问题，性能指变得更快或更轻量，
稳定性指不会再崩溃、停机、泄漏或丢失数据，修复指曾经给出错误结果的问题。`x.y.0` 版本在标题下有一行简短的标题：
应用将它用作整个系列的大标题。

## [2.3.1] - 2026-10-26 to 2026-10-28

### Security
- **设置向导需要一次性代码**：在完成设置之前，FinStats 每次启动都会把一个代码写入日志（`docker logs finstats`），向导在测试地址或进行任何设置之前都会要求输入它。否则，最先访问到该端口的人可以把 FinStats 指向自己的 Jellyfin 并成为其管理员，或借助测试功能探查网络。
- **媒体库访问权限跟随 Jellyfin**：每个人只能看到 Jellyfin 向其开放的媒体库，并且在其中只能看到 Jellyfin 按其分级上限、标签和未分级规则为其列出的标题，这适用于媒体库页面、搜索、演职人员、图片、最近添加、待看清单、即将上线、日历订阅源以及新标题通知。此前每个已登录的人都能浏览所有媒体库。
- 链接可能在用户登录后立即把他从欢迎页送到其他网站。现在只会跳转到 FinStats 自己的页面。
- 服务器日志和洞察中的登录失败记录，会把所有人的登录地址和活动提供给拥有*查看服务器*权限的任何人。现在他人的记录需要*查看所有人的活动*，地址需要*查看网络详情*，与其他地方一致。
- 个人通知目标可能通过一个第二次查询时解析结果不同的名称访问本地网络。现在会连接到经过检查的那个地址，更多永远不会通向互联网的地址段被视为本地，家庭自己的公网地址也会被拒绝，无法解析的名称会以与本地名称相同的措辞被拒绝。
- 在会自行添加一行 `X-Forwarded-For` 的代理之后，或来自 IPv6 网络时，每次登录尝试都可能来自新地址，次数限制从不生效。现在一个 IPv6 /48 在五分钟内有 50 次尝试机会，限制表已满时拒绝新地址而不是遗忘旧地址，整个服务器在每分钟 60 次失败时停止接受登录，每个地址在每个时间窗口内的登录失败只审计一次。
- `FINSTATS_TRUST_PROXY` 指定其 `X-Forwarded-For`、`X-Forwarded-Host` 和 `X-Forwarded-Proto` 可信的代理（地址或地址段），而 `1` 或 `true` 现在只信任环回或私有网络上的对端。此前开启时，任何对端都可以自选地址；在代理之后不开启时，十次错误猜测就会把所有人锁在外面。
- 读取用户之后，对于未知、已停用、已删除或未获准进入 FinStats 的名称，登录会不询问 Jellyfin 而直接按密码错误作答，且不会早于 Jellyfin 本该作答的时间。此前这些名称可能锁定 Jellyfin 账户、绕过 Jellyfin 的远程访问规则，或躲在 FinStats 的地址后面。
- 被 Jellyfin 限制在家庭网络内的人（关闭了*允许远程连接*）只能从家庭网络登录 FinStats，因为 Jellyfin 是根据 FinStats 自身的地址来判断这个开关的；没有说明某人是否被停用的用户读取结果会把他拒之门外。
- 只要登录页面使用 https，会话 cookie 就会被标记为 Secure，即使在不声明这一点的代理之后也是如此。
- 成功登录不再清除之前的猜测次数。在 https 下，会话 cookie 是 `__Host-` cookie，相邻域名上的网站无法替换它，也不会以其他名称接收；退出登录会结束浏览器发送的每一个会话。
- 只有日历密钥可以通过地址打开日历订阅源；其他任何密钥都要放在请求头中。
- API 密钥不再能授予权限、更改谁能进入或哪些内容公开、还原备份，或添加、更改、测试服务或通知目标：这些都比密钥存在得更久，因此需要已登录的浏览器。
- 每个响应都带有 `Cross-Origin-Opener-Policy: same-origin` 和 `Permissions-Policy`，API 响应带有 `Cross-Origin-Resource-Policy: same-origin`，除非另有说明均为 `no-store`，CSP 也不再允许 `blob:` 图片。此前打开 FinStats 的页面之后可以把它的标签页变成自己的登录页。
- 当 FinStats 知道访问它所用的协议时（可信代理的 `X-Forwarded-Proto`，或公网地址），来自其他协议的写入会作为跨站请求被拒绝。
- `/auth/me`、标题页面和媒体库健康以 Jellyfin 的公网地址链接到 Jellyfin；FinStats 自己读取 Jellyfin 所用的地址只提供给管理员。
- 只为 FinStats 拥有的内容从 Jellyfin 获取图片，包括公开资料的海报和卡片，因此无法按 ID 请求其他媒体库的图片。
- 下载队列的错误信息中也会抹去私有 tracker 的密钥，既按名称也按形状识别；只拥有*查看下载内容*权限的人会被告知哪个服务失败以及如何失败，但绝不会看到其内部地址或重定向目标。
- 服务器页面只在拥有*查看所有人的活动*权限时显示设备的最后使用者；未关联媒体除了*管理 FinStats*之外也需要这项权限。没有这项权限时，任务部分只统计自己的播放和串流，已删除的媒体库按自己的播放列出，等待中的 Tautulli 连线板也无法取消。
- 设置中只以主机名显示公网地址服务，Jellyfin 的地址和数据文件夹只向管理员显示；媒体库已丢失的标题只根据读者有权查看的播放记录来描述。
- 表不是普通表的 Tautulli 备份，可能让其他所有写入一直等待，直到 FinStats 重启。现在这类文件会被拒绝，SQLite 也以防御模式读取备份。
- 超过 4 GB 的上传会被拒绝，压缩的 Tautulli 备份解压时不会超过它声明的大小；两者都可能填满 FinStats 自身数据库所在的磁盘。
- 来自 Jellyfin、Sonarr、Radarr、Seerr、公网地址查询或 GeoIP 下载的响应，读取时不会超过其允许的上限，按解压后的大小计算。
- 任何 Jellyfin 用户都可以通过上报同一标题的成千上万次短播放，让 FinStats 停止为所有人记录播放。现在判断谁一起观看只需一遍处理，处理期间不持有任何锁。
- 首尾相接记录的播放，或在一台又一台设备上轮流播放的同一标题，不再把陌生人合并到一个组里；对只能查看自己的人，只告知与其本人播放同时进行的人，以及同时进行的时长。
- 链接仍可能通过 `/.//` 这样的路径，在登录后把用户从欢迎页送到其他网站。
- 管理者不再能更改保留的备份数量或写入频率、合并时间窗口（现在最多一小时），或读取用户、活动日志和备份的时间，管理者的备份也绝不会挤掉管理员的备份；家庭地址和出行规则需要与警报相同的权限，导入历史还需要*查看所有人的活动*。
- 保存的密钥、令牌或密码只会发往保存时对应的服务器；通知目标只能在登录状态下创建或更改，绝不能用 API 密钥。管理员可以停用或删除他人的个人通知目标，但不能把它指向别处、关闭其证书检查，或读取其 ntfy 主题或 Pushover 用户密钥。
- Discord 和 Slack 的 webhook 必须使用 `https`，因为它们的地址就是令牌。
- 大量失败登录不再能掩盖真实的登录或淹没警报：不存在的账户名每十五分钟只产生一条不点名任何人的通知，警报优先发送，Slack 和 Discord 以纯文本显示消息内容，且不提醒任何人。
- 年度回顾的排名、容量、通知和公开资料透露的内容不会多于页面：不向只能查看自己的人显示排名或所有人时间中的占比，没有*查看所有人的活动*权限时，繁忙时刻只显示为有三路或以上播放的日期，不向无权管理 FinStats 的人告知失败的任务或连接，公开资料每天只变化一次。
- 含有生成列的 Tautulli 备份会被拒绝；导入的播放只有在媒体库拥有其标题后才会获取图片。
- 还原绝不会让 FinStats 比现在更开放：只在要求时才恢复设置，登录、权限和公开资料取本安装与备份都允许的部分，公网地址保持本安装自己的。`finstats restore <file>` 与页面一样只恢复历史，加上 `--with-settings` 时才同时恢复设置。
- 只还原历史时不再带回家庭地址、已静音的警报、冒充本安装自身的审计条目，或媒体库中没有的已定位标题；任何还原都不会带回日期早于 1990 年或晚于明天的播放、日志行或设备。还原的播放无论声称来自何处都算作导入，因此重启后绝不会继续它。
- 数据文件夹只属于 FinStats 自己的用户（0700，其中文件 0600，镜像中 `umask 077`）。FinStats 拒绝以 root 身份在其他用户拥有的数据文件夹上运行，并给出应使用的 `docker exec -u`；入口脚本只更改该文件夹及 FinStats 自身条目的所有者。
- 通知目标的名称不能包含控制字符，设备、人员或标题的名称也不再能在日志中伪造一行。
- 链接的路由参数不再能访问其页面之外的其他 API 路径，FinUI 的元素构建器只在地址为 http(s) 或相对地址时才设置地址，绝不设置 `srcdoc`。
- 搜索、公开资料和手动启动的任务不再能让 FinStats 忙不过来：搜索最多 200 个字符，公开资料按语言分别缓存，卡片在一个短队列中等待，任务、地址查询、位置数据库下载和测试消息无论以何种方式请求都有启动频率限制，测试消息按发送者计数。获取位置数据库还需要与阅读安全页面相同的权限。
- 请求正文在前 15 秒过后必须持续到达，没人读取的应答在 30 秒后放弃，一个地址最多保持 64 个连接（受信任的代理除外）。几百个从不发送正文的请求曾能让 FinStats 无法回应任何人。
- 邮件服务器的应答最多只读到任何应答都不会超过的量（整封信 1 MB），测试消息在队列消息允许的时间后停止。一个从不结束一行的服务器曾能让 FinStats 占用越来越多的内存，直到它被停止。
- 媒体库读取以读取所存的标题为准，而不是导入带来的标题；已读取过的媒体库中的 Jellystat 标题以已移除的状态导入。导入虚构的标题曾能让每次媒体库读取都在每次启动时停止 FinStats。
- 全服务器每分钟 60 次登录失败的上限只计算交给 Jellyfin 的尝试，包括仍在等待其回答的尝试。FinStats 自己拒绝的名字曾让任何拥有几个地址的人阻止所有人登录，而同时发出的大量猜测都会到达 Jellyfin。
- 被 Jellyfin 限制在家庭网络中的人，在每个请求中（包括其会话和密钥）都受此限制，而不只在登录时；家是私有网络或查询到的家庭公共地址，从不是手动填写为家的地址；在 `FINSTATS_TRUST_PROXY` 未列出的代理之后，此人会被拒之门外。带出家门的 Cookie 或密钥曾能在任何地方打开一切，管理者也曾能为自己选定的地址打开家门。
- API 密钥再也不能关掉会发现它被滥用的东西，或能撤销它所做之事的备份：保留多少备份及多久一次、合并时间窗、家庭地址和出行规则、用户、活动日志和备份的计划、静音或解决所有警报、把备份移入回收站，或删除通知目标。每一项在密钥被吊销后都仍然有效。
- Sonarr 和 Radarr 的海报以及想看列表的下一集也遵循媒体库访问权限：Jellyfin 对某人隐藏的剧集，对他既没有海报也没有日期。逐个数服务的 ID 曾能看出哪些隐藏的剧集即将到来，列表也曾说出隐藏剧集的下一集。
- 年度回顾的“一起看”章节与“一起看”页面一样，只列出与你同时播放的人。通过别人加入的分组曾列出从未与你一起看过的人。
- Jellystat 或 Streamystats 导入会先读完整个文件，再取得数据库的写锁，然后只写入保留下来的行。在锁内读取时，一个只有少量真实行、其余是数 GB 任意内容的文件，曾让其他所有写入（包括播放和登录）一直等待。
- 恢复时每人只保留一条权限，人数不超过一个家庭的许多倍，检查审计记录是否重复时也不再重读刚写入的每一条。精心构造的备份曾能在恢复过程中越来越久地占用内存和数据库写锁。
- 连同设置一起恢复时，只有在本安装也开启的情况下才会开启公共地址查询和位置数据库下载，且保留的备份数量和写入频率绝不少于本安装。一个只保留一份的备份曾能让下一次运行删除其他所有备份。
- 任何磁盘都装不下的文件大小会被视为没有大小，而且大小的相加方式保证任何总和都不会溢出。一个导入的大小曾让媒体库页面永久报错。
- 一旦 FinStats 知道自己经由 https 访问（其公共地址是 https，或受信任的代理这样说明），会话只从 `__Host-` Cookie 中读取；公共地址为 https 时，每个新会话都是 https 会话。经由什么都不说明的代理、不带 `Origin` 发出的登录曾会生成普通会话，相邻站点可以把它塞进别人的浏览器。
- 镜像构建时每个 GitHub 动作都固定到某个提交，两个基础镜像固定到摘要，只有 Dependabot 会移动这些固定点；发布版本构建时不使用共享的构建缓存。别人动作的标签一旦被移动，曾可能把任意镜像当作 FinStats 发布。
- 按访问者自己的外观绘制的 FinUI 样式表只能由 FinStats 自己的页面加载。同一主机其他端口上的页面曾能从中读出访问者是否已登录以及选了哪个预设。
- 每次被拒绝的登录，无论是 FinStats 还是 Jellyfin 拒绝，都在从发送时算起的同一时刻作答；名字的匹配不分大小写，A 到 Z 以外的字母也一样。拒绝来得多快曾能透露哪些名字是真实用户，输入 `åse` 的“Åse”也曾在未询问 Jellyfin 的情况下被拒。

### Performance
- 公开资料最多每分钟计算一次，不再为其中每张图片和卡片重新计算。
- 无论开始多少次播放，同一个人的历史每次只进行一次安全警报扫描。
- 登录或退出、吊销密钥或更改某个人的授权时，只让与之相关的实时连接重新检查。
- Tautulli 连线板只读取一次历史，而不是每个 Plex 用户读取一次。
- 缓存中缺失的图片由一个请求获取，其他请求等待；来源未能提供的图片在 30 秒内不会再次请求。
- Web 界面的文件只压缩一次 gzip 并保存下来，字体不再重复压缩。

### Stability
- Jellystat 旧格式的备份逐行读取，而不是整体读入；比任何备份中的行都长的行会被拒绝。
- 同时进行的两个 Tautulli 上传不再写入同一个文件。
- 远超媒体库标题列表或媒体库健康末尾的页码会得到空白页，而不是错误。
- 上传中断的导入或还原不再让其他所有导入和还原在重启前都被拒绝，它以及在开始前就被放弃的导入都不会留下文件。
- 备份中的单行最多读取 8 MB，并且一次只接收一个 Tautulli 备份。
- 一次播放最多保留 2,000 个事件，导入会跳过不是在 1990 年到明天之间开始并结束的播放。
- 一个远小于零的集号不再让每次媒体库读取卡住：媒体库健康（包括其摘要）、容量、重新关联和定位在相加和比较数字时不会回绕，发布版本会检查溢出，因此任何遗漏只会让一个任务停止，而不是陷入循环。
- 季号、集号或结束集号只在 Jellyfin 能容纳的范围内（0 到 2,147,483,647）保留，无论来自 Jellyfin、Jellystat 还是 Tautulli。
- ID 重复的 Tautulli 备份会被拒绝，因为同一 ID 下几 MB 的行就能耗尽进程内存；备份以不可变方式打开，不会留下 `-wal` 或 `-shm`。
- 连接必须在 15 秒内发送请求，同时最多服务 512 个连接：几百个半开的套接字就曾让 FinStats 离线。实时通道上的帧限制为 4 KB。
- 来自 Sonarr、Radarr 或 Seerr 的几 KB 数据不再能变成几 GB 内存：列表只保留 FinStats 会读取的部分。
- 从不响应的通知目标只会拖慢它自己：各目标并行发送，持续超时的目标会被搁置十分钟。
- 队列的剩余时间和总速度、还原的播放中的数字以及播放离开回收站的日期不再会溢出。
- 还原在获取写锁之前先读完整个文件，拒绝解压后远大于其大小的文件，并分批写入，因此收集器在此期间继续记录。
- 备份以 UTC 命名，绝不覆盖已有文件，并且只清理 FinStats 自己的更新前副本。
- 日期在未来的服务器日志行不再阻止读取活动日志：会从其最新的、不在未来的行开始读取。
- 同时到达某个公开链接的请求只计算一次其响应，其卡片在单独的通道中绘制，因此持有链接的人不再能让所有者的年度回顾卡片返回 503。
- Jellyfin 媒体库列表中缺失的媒体库，其播放记录会等待两天，才会移到另一个媒体库中同一标题的副本上。一次漏掉某个媒体库的列表曾立即移走这些记录，媒体库回来后也没有移回。
- Jellyfin 报告的磁盘大小超出任何数字的容量时，不再导致每次读取服务器详情都失败。
- 当页面重复且没有新 ID 时，停止从 Jellyfin 读取。

### Fixed
- 某个账户的登录失败在每个时间窗口内只产生一条警告，达到二十次时升级为警报；只有完整输入的名称才计入该账户（“x alice”不再计入 alice）。

### Performance
- **开着不动的页面不再发出任何请求**：仪表板为保持最新每分钟发出 30 次请求，待入库的下载每分钟 18 次；有了实时通道，两者都不再发出请求。无论打开多少个标签页，FinStats 向 Jellyfin、Sonarr 和 Radarr 发出的请求都不比以前多，隐藏的标签页仍会让下载队列放慢查询。
- 个人页面只读取这个人的播放：以前其总计和最后一次播放要先对服务器上的所有播放进行计算再筛选到此人，100 万次播放约需四秒。
- 媒体库页面只读取该媒体库的作品和播放，以前它统计所有媒体库后只保留一个：100 万次播放时耗时减为三分之一。
- Jellyfin 的时钟比 FinStats 快时，*Jellyfin 媒体库扫描之后*会每分钟重新读取整个媒体库，直到时间差过去；现在每次扫描只跟进一次。
- 无法打开的 GeoIP 文件每隔一刻钟就被重新复制一次（一百多兆字节），所有地址也重新定位一次；现在只有文件变化后才会重试。
- 指针在媒体库健康的链接上停留后，该页面立即打开：以前预先获取的数据存放在页面从不查找的地方。

### Stability
- 如果一次更新在迁移运行之后失败，而 Docker 立即重启它，每次启动都会为更新到一半的数据库新建一份副本，三次启动后，上一版本唯一能打开的那份副本就被清理掉了。现在会保留更新前的副本。

- 恢复一份在文件重命名或升级之前创建的备份时，此后已移到新文件上的所有播放会再被恢复一次，永久重复。
- Seerr 应答中 FinStats 无法读取的请求（Seerr 更新后某个字段改了名）会被每日的完整读取标记为已移除。
- 遇到程序错误的任务会永远停在“运行中”，在 FinStats 重启之前，任何触发器都无法再次启动它；现在它会以失败结束。
- 损坏的 Tautulli zip 文件会让上传中途停止，没能删除这个包含所有 Plex 用户令牌的文件，直到六小时一次的清理才删除。
- 在文件上传过程中被终止的导入或恢复，会把该文件永远留在数据目录中，连同其中的地址；现在下次启动时会将其删除。
- 图片在缓存过程中可能只写入一半就被发送出去，浏览器随后便一直保留这个残缺的版本。
- 已吊销的 API 密钥会被永久保留，无论创建和吊销了多少个。

- **不再使用对话框的搜索**：搜索从菜单中展开（侧边栏变宽、程序坞升起、命令栏的名称变成搜索框、手机菜单容纳它），或者在“设置 → 外观”中选择后，在菜单保留的同时取代页面内容。Ctrl+Space 仍然可以打开它；覆盖一切的窗口已经去掉。即 FinUI 的 `search`。
- **媒体库中的全部内容**：媒体库的最近添加卡片提供*全部内容*，以海报列出其中的每部电影、剧集或专辑，可按名称、年份、添加日期或大小排序，输入时即时筛选。滚动时加载更多。
- **服务器 → 媒体库健康**：FinStats 把每个文件与相邻的文件比较，列出不寻常之处，每条都附有依据的数据。它只做报告，不会在 Jellyfin 中更改、删除或重新扫描任何内容。
- **缺集**：一季中两个文件之间缺少的集（“第 2 季：第 3 集和第 6 集之间缺少第 4、5 集”）。包含两集的文件算作两集；特别篇和季末不做判断。
- **与众不同的季**：分辨率、HDR 或编解码器与该剧其他季不同；以及**格格不入的集**：与所在季不同的单个文件，例如 1080p 季中的一集 SD。分辨率按宽度或高度判断，因此裁切为 1920×800 的电影算作 1080p。
- **副本与版本**：同一部电影或同一集出现两次，依据的是待看清单和待入库已经在用的提供商 ID。同一分辨率的两份副本会显示重复占用的空间；4K 副本与 1080p 副本并存时列为两个版本，绝不算作浪费。
- **码率过低的文件**：比特率远低于其分辨率和编解码器通常所需（“4K HEVC，1.1 Mbps”）；一季中码率过低的各集合为一条问题。
- **中途停止的配音**：某种音频语言在一些季的每一集都有，在另一些季则一集都没有。
- **从未识别**：Jellyfin 匹配后没有任何 TMDB、TVDB 或 IMDb ID 的电影和剧集。
- **忽略**有意为之、没有问题的条目，并附上备注。文件发生变化时，它会自动重新出现。能管理 FinStats 并能查看服务器的人可以忽略问题；忽略操作记录在审计日志中，并包含在备份里。
- 媒体库页面会显示该库中有多少处需要查看，并提供链接。
- **FinUI** 是构成 FinStats 的组件库，现在成为一个独立项目（`github.com/finstats/finui`）：在 `finui.finstats.no` 可以看到每个按钮、卡片和控件的所有状态以及两种主题；**FinUI create** 可以边看边调整颜色、圆角、密度等，并用一条命令带回家。**设置 → 系统** 中有链接。
- **设置 → 外观**：每个人都可以通过 FinUI 预设的代码选择 FinStats 在自己眼中的样子：基础色、强调色、图表颜色、对比度、圆角、密度、边框、卡片、按钮、输入框、表格、高亮、动效、图标、菜单、背景页面、焦点环、标题的排版，以及正文、标题和数字的字体。你的选择只属于你自己；页面会说明代码的含义，并链接到 FinUI create 以便修改。
- **风格**：FinUI create 中有十一种完整外观，一次选择即可作为起点，其代码可在“设置 → 外观”中使用。它们是 Washi（FinStats 出厂时的样子）、Studio、Noir、Matinee、Console、Pastille、Ledger、Gazette、Arcade、Canopy 和 Harbour。FinStats 本身只提供一种外观，不提供风格列表。
- **会动的图标**：链接、按钮或标签中的每个图标在指针指向时都会做一次自己的动作（刷新会转动，下载的箭头落入托盘，回收站掀起盖子），按下的刷新按钮会一直转动，直到收到应答。开启“减少动态效果”或动效设为“关闭”时保持静止。
- **FinMotion 带来的动效**：FinUI 的组件现在会动了：开关的滑块被甩到另一边，标签的下划线挪向下一个标签，被拒绝的输入框会摇头，复制成功时一笔打勾，通知像一手纸牌那样叠起、指针指向时呈扇形展开，手机上的面板被拉动时像橡皮筋一样有弹性，排序后表格的行移到各自的位置，变化的数字像里程表一样滚动，图表在第一次出现时自行绘制。这一切都遵循“设置 → 外观”中的动效选择，开启“减少动态效果”时保持静止。FinMotion 是一个独立项目（`github.com/finstats/finmotion`），叠加在 FinUI 之上。
- **FinUI 中更多图标**：从 71 个增加到 239 个，每个都有自己的动作（音量增减、耳机和静音耳机、会写字的铅笔、会响的铃铛、会振动的手机），每一个都可以从 FinUI 的图库下载为 SVG，静态或动态皆可。
- **字体**：三十四种开源授权字体可选（Geist、Roboto、Manrope、IBM Plex Sans、Montserrat、Lora、Playfair Display、Fira Code 等），与 Inter 一样随程序附带，从不从别处获取，并且只在选中时加载。
- **更多基础色和强调色**：Nord、Solarized、Gruvbox、Catppuccin、Rosé Pine、Tokyo Night、Dracula、Everforest 和 Ocean；另有十六种强调色，其中十种白天一种颜色、夜晚另一种颜色。现在每种基础色在白天都有自己的纸色：在浅色主题下，各种灰色看起来都差不多。
- **删除可在 30 天内撤销**：删除的播放或备份会在回收站中等待，随后出现的提示上的**撤销**可以把它找回。只要有最近删除的内容，活动和“设置 → 备份”都会列出它们，并注明何时永久删除。回收站中的播放不计入任何总计、图表、年度回顾和资料，导入或恢复也不会把它当作新播放带回来；和别人一起看过它的人，在它恢复之前会被算作独自观看。

### Changed
- Dark Reader 及类似扩展不再改动 FinStats 的页面（`darkreader-lock`）：FinStats 自己绘制两种主题，被重新着色的页面会与之冲突。
- 手机上的菜单不再从左侧滑入：除非选择了其他菜单，标签栏位于底部。

- 在作品页面上，**加入待看清单**与旁边的**在 Jellyfin 中打开**一样高；以前它小一号。

### Performance
- 打开 FinStats 时只下载有变化的内容：浏览器已有的样式表、脚本或字体只需几个字节确认，而不用重新发送。以前每次访问都会完整获取 FinStats 的所有样式表和模块，尽管每个文件都带有用来区分版本的标签。

### Stability
- 恢复备份时只从设置行读取设置：来自较新版本 FinStats、在那里保存了更多内容的文件，其设置会被悄无声息地丢弃。

### Fixed

- `finstats --help` 列出 FinStats 读取的每个变量；以前缺少 `FINSTATS_PUBLIC_IP_URL`、`FINSTATS_ALLOW_LIBRARY_SHRINK` 和 `FINSTATS_SKIP_PREUPDATE_BACKUP`。
- 设置向导对于根本不是地址的输入，会说“couldn’t connect”，而且这句话和下一句连在了一起；现在它会说明这不是一个地址。

- 菜单为可展开的图标栏时，关闭搜索会同时显示展开的搜索和收起的图标栏，然后图标栏一直保持展开，直到指针移入又移出。现在按 Esc 会把键盘焦点交还给搜索打开时它所在的位置，点击产生的焦点则会释放。

- 在搜索完全打开之前就关闭它，会让可展开的图标栏失去动画：此后它打开和关闭都是瞬间完成。
- 可展开的图标栏在从中选择页面后会保持展开，直到在其他地方点击；在某些浏览器上或放大时，还会在图标下方画出滚动条。现在它只为指针和键盘展开，收起时不画滚动条。

## [2.0.4] - 2026-09-29

### Added
- **像 Jellyfin 一样安排任务**：FinStats 自行执行的每个任务都有触发器（每天某个时间、每周某一天、按间隔、启动时，或在 Jellyfin 媒体库扫描之后），每个触发器都可以设置时间限制。点击任务即可查看和更改其计划；*添加触发器*会打开与 Jellyfin 相同的对话框。
- **任务成为设置中独立的一节**，每个任务的上次运行用文字描述（“上次运行：38 分钟前，耗时 6 分钟”），并有一个运行按钮；以前它位于系统的顶部。
- **元数据变更**：FinStats 每小时读取 Jellyfin 自上次查看以来保存的内容（名称、简介、类型、评分、演职人员、文件详情和图片），因此在 Jellyfin 中的编辑无需等待媒体库扫描即可显示。
- 备份和地理位置数据库也可以从任务中运行；按 Esc 可从任务的计划返回列表。

### Changed
- **主题改为三档开关**：浅色 · 跟随设备 · 深色，取代原来循环切换的按钮：点击其中三分之一、拖动滑块或使用方向键。滑块上显示所选项的图标，切换时图标会滑入。
- **退出登录移到“设置 → 账户”**，那里会显示当前登录的是谁；侧边栏保留主题开关。
- **旧的计划设置现在是触发器**：*跟随 Jellyfin 媒体库扫描*及其后备间隔、*每 N 天备份一次*以及 GeoIP 的*保持数据库为最新*开关，都按你原来的值变成了相应任务上的触发器。采集、备份和安全改为链接到计划。
- 启动时不再把每个任务重新运行一遍：会记住每个任务上次完成的时间。
- 还没有估计时间的 Jellyfin 后台任务显示“约剩 …”，圆点在时间将出现的位置循环闪动，而不是“ETA…”。

### Performance
- **安全页面的地图不再卡顿**：拖动和缩放只是移动已经画好的地图，手势结束后才重新绘制一次；“正在播放”的脉冲也不再在无人操作时让整张地图每秒重绘 120 次。在一台较慢的电脑上，拖动从每秒 34 帧提升到 60 帧。

### Fixed
- **在 Jellyfin 中替换的海报或人物照片会在 FinStats 中显示**：以前无论 Jellyfin 后来有什么变化，图片都在服务器上缓存一周，在浏览器中再缓存一周。现在以 Jellyfin 的图片标签缓存，新图片就是新文件，浏览器每次显示时都会检查自己的副本是否最新。替换人物照片只会重新保存该人物，因此元数据变更也会读取人物。
- **服务器 → 后台任务在页面打开时就显示估计时间**：以前剩余时间只根据页面打开期间自己的读数计算，因此每次访问都从“ETA…”开始，直到看到百分比变化。现在 FinStats 会自行为正在运行的 Jellyfin 后台任务计时，运行期间每 10 秒一次，页面直接获得估计值。Jellyfin 始终报告为 0% 的任务（媒体库扫描的第一阶段）在百分比变化之前保持显示圆点：绝不猜测。
- **地图提示框出现在圆点上**：在 Firefox 中，“正在播放”圆点的提示框可能出现在很远的地方；圆点重叠时（有人在家播放），显示哪个提示框取决于一个像素。现在一个提示框会列出指针下的所有内容。
- **状态栏只有一种悬停样式**：每个链接（播放、仓库、版本号）都亮起为同样的小方框，各项之间的圆点居中位于间隙中。以前悬停在版本号上时，前面的圆点和间隙也会一起亮起。

## [2.0.2] - 2026-09-28

### Security
- 在代理之后，登录次数限制统计的是第一个 `X-Forwarded-For` 地址，而这是客户端自己发送的：每次尝试换一个编造的地址，限制就永远不会生效。现在使用最后一个地址，即代理写入的那个。
- 开启*包含 IP 地址和地点*后，地址会被发送到所有者没有*查看网络详情*权限的个人通知目标，而任何页面都不会向他们显示这些地址。现在别人的登录失败还需要*查看服务器详情*权限，与安全页面一致。

### Stability
- **停机请求绝不会丢失**：以前在启动后的最初片刻、服务器尚未开始监听时，如果媒体库读取被拒绝，这次拒绝会被记下，但 FinStats 继续运行而没有停止。
- **以 FinStats 无法读取的格式应答的 Jellyfin 会被拒绝**，而不是被信任：以前所有用户或某个媒体库的所有作品以它不认识的键名到来时（`id` 而不是 `Id`），会带着完整的数量通过检查，随后被标记为已移除。
- **播放的结束绝不会丢失**：以前数据库繁忙超过等待时间时（例如被导入占用），恰在那一刻结束的播放会一直标记为正在播放，直到下次重启。现在它会在下一轮写入。
- **恢复时无法读取的设置保持不变**：以前设置与当前版本不再匹配的备份，在恢复时会重置所有设置：合并时间窗口、权限、家庭地址、计划。
- **名称或标题中的控制字符不再弄坏卡片**：以前资料卡片、显示该作品的每张故事卡片以及它们的 ZIP 都会返回错误。

### Fixed
- **在 Jellyfin 中被禁用或删除的人不再收到通知**：以前他们的个人通知目标会继续收到其旧权限所允许的一切。
- **排队中的通知在发送前会再次确认**：以前已关闭的通知目标，或已失去某项权限的所有者，仍会收到等待重试的内容。
- **始终应答 `Retry-After` 的通知目标**会像其他目标一样在五次尝试后放弃，而不是重试三十天。
- **个人页面上的设备 ID** 只在拥有*查看网络详情*权限时显示，与其他地方一致。
- **公开的年度回顾对所有内容都延迟一天**：以前其中看完和弃看的剧集会跟随每次播放更新，因此在一部弃看的剧集上按下播放，几秒钟内就会改变公开页面。
- **请求的剧集只要有一集被观看就算作已观看**：以前在年度回顾的请求章节和请求卡片中，每部请求的剧集都显示为从未观看。
- **年度回顾的结伴章节不计电视直播**，与这一年的其他部分一致：以前一起开着的频道可能成为排名第一的作品，占比也可能超过 100%。
- **“过去 12 个月”的每一天卡片在最新的一天结束**：以前网格会漏掉最近三四周。
- **剧集的新单集每晚只通知一次**：以前在 UTC 以东或以西的服务器上，UTC 午夜前后的单集会被通知两次。
- **连接 Seerr 时不会把旧请求通知为可以观看**：以前首次读取时就已可用、又没有其他时间记录的请求，会被当作此刻刚到。
- **在 Jellyfin 中删除的媒体库，其作品随之移除**：以前它们会留在搜索、最近添加栏和总计中。
- **当某次读数暂时丢失转码详情时（跳转时），重新封装的播放仍算直接串流**，而不是在剩余的播放中都变成转码。
- **“Jellyfin 已离线”意味着连续多次读取失败**：以前在通过 WebSocket 连接、处于空闲状态的服务器上，相隔几天的零星超时也会累积成这个结论。
- **Streamystats 导入在它自己的卡片上显示进度**，而不是覆盖在 Jellystat 导入的上次结果上。
- **主机名以“web”开头的地址**（`http://web:8096`）会被识别为主机，而不会被当作 Jellyfin 网页客户端的路径截断。

- **从 Streamystats 导入**，在设置中与 Jellystat 并列，有自己的一节。拿到它的 **Settings → Backup & Import → Download Backup** 文件，拖进来即可：多年的历史几秒钟就能导入，已有的内容不会重复计算。`finstats import-streamystats <file>` 可在无界面环境下完成，API 中为 `POST /api/import/streamystats`；同一时间只运行一个导入，无论哪种。
- **两个追踪器都用过？两份文件都导入。**如果追踪器为某次播放提供的 ID 已经存在，FinStats 就认为已有这次播放；否则，同一个人观看同一项内容、且播放的任一端与历史中某次播放接近，也视为已有。因此同样几个晚上的 Jellystat 导出和 Streamystats 导出可以都导入，顺序不限，FinStats 自己记录的夜晚也不会被任何一方覆盖。“接近”指的是“设置 → 采集”中的合并时间窗口。
- 导入的记录不会编造它们无从知道的内容。Streamystats 自己记录的播放不保存任何文件信息（没有编解码器、分辨率、比特率或容器），因此这些字段保持为空，而不是用猜测填充，本应显示它们的卡片会自行隐藏。它从 Jellystat 获取的播放带有完整的会话，因此改为读取会话：以播放结束的时刻为准（这是两个追踪器都保存的唯一时刻），并且只有当会话确实是转码时才记为转码。
- Streamystats 因 Jellyfin 报告某项内容已观看而写入、实际上它从未见过观看过程的记录，会被计数并跳过：这些记录与整部电影一样长，会在无人观看的晚上变成观看时长。结果会说明有多少条。
- Streamystats 数据如何逐字段解读，是从真实导出文件而不是文档中摸索出来的：`docs/streamystats-import.md`。
- 活动页面上的**每次播放来自哪个追踪器**筛选器：FinStats 自己记录的、来自 Jellystat 的、来自 Streamystats 的。只提供你的历史中实际存在的来源，并且与其他列表一样受权限范围限制，只能查看自己播放的人只会知道自己的历史来自哪里。
- **活动页面的筛选器是可以勾选的下拉菜单**，因此可以同时查看电影*和*剧集而不含音乐、两种播放方式或两个人，而不是每样只能选一个或全选。由于现在可以组合，媒体类型新增了**其他**。
- 凡是出现用户筛选器的地方（仪表板、播放、媒体库、安全等），都可以同时选择多人，地图和每项统计都随之变化。用户筛选器仍然只会缩小一个人能看到的范围：没有*查看所有人的活动*权限时，无论地址中写的是谁、写了多少人，请求都限定为调用者本人。
- **浅色主题**：和纸般的底色，墨色文字和朱红色强调色。在你选择之前，FinStats 跟随设备的浅色或深色设置。
- **退出登录旁的主题按钮**依次切换跟随设备、浅色和深色。选择保存在当前浏览器中，并在页面绘制之前应用，因此绝不会闪现另一种主题。
- **在 Jellyfin 中打开**：每个电影、剧集和单集页面都有一个按钮，在新标签页中打开该作品在 Jellyfin 中的页面。
- “设置 → Jellyfin”下的**供用户访问的 Jellyfin 地址**：这些按钮指向的地址，用于 FinStats 连接的地址无法从浏览器访问的情况。留空则使用 FinStats 连接的地址；只有 Jellyfin 管理员可以设置。

### Changed
- **FinStats 搬家了**：`github.com/finstats/finstats`，镜像为 `ghcr.io/finstats/finstats`。请在 `docker run` 或 compose 文件中更改镜像名称，以继续获得更新；数据文件夹保持不变。
- **设置页面一次只显示一节。**以前这个页面是一栏十四张卡片和六百字的帮助说明。现在每一节都有自己的地址（`/settings/collection`），左侧的列表用于在各节之间切换，在手机上列表会折成一排标签。指向旧锚点的链接仍然有效。
- **一项设置占一行**：它是什么、一行说明规则、控件在右侧。一节中的数字设置通过底部的一个按钮一起保存；开关仍然自动保存。状态卡片（任务、出站连接、数据库）和许可证链接位于**系统**下，两个导入器各有自己的一节。
- **查找设置**：在页头的搜索框中（按 `/` 聚焦）输入设置名称中的任意词语；它会说明该设置位于哪一节，按 Enter 会跳到那一行。
- **设置对所有已登录的人开放**：管理服务器的各节仍只对有权管理的人显示，只被允许接收通知的人终于可以访问自己的通知目标了。
- **服务器页面一次只显示一节**，与设置相同：概览（系统和存储）、后台任务、设备、插件、日志和审计日志，各有自己的地址。指向 `/server#jobs` 的链接仍然有效。
- **服务器日志成为服务器页面的一节**（`/server/log`），而不是菜单中的独立页面；`/events` 会带着筛选条件跳转到那里。
- 关于任务失败、备份失败或连接停止响应的通知，会链接到相应的设置节，而不是页面顶部。
- 你的媒体库能为导入的播放提供的信息（它是什么类型、哪一集、时长、属于哪个媒体库）会在**每次**媒体库读取之后补全，而不只是在导入的那一刻。历史通常在 FinStats 读取媒体库之前就已导入，因此这些播放以前会一直停留在猜测或未知的状态。
- 恢复 FinStats 备份时，不再添加以另一个 ID 从追踪器导入的播放，同时仍然保留相隔几分钟的两次真实观看。
- 播放详情会写明是哪个追踪器带来的，而不是把所有导入的内容都称为 Jellystat 播放。

### Performance
- **无论历史多长，重启几乎瞬间完成。**以前每次启动都要在整个历史上计算谁和谁一起看，并重新判断哪些播放来自本地，而这两项都不会改变任何东西：在一千万次播放上分别耗时 24 秒和 5.5 秒。现在启动时只处理上次运行遗留的部分，只有在更新之后或相关设置改变时才全部重新处理。
- **一大群人同时到来，几秒钟内就能记录下来。**以前每次新播放、每次进度保存和每台设备都单独写入，每次结束的播放都要单独查看该作品的整个历史；现在每一轮对每类数据一次性写入。100,000 次播放同时开始只需 3 秒，而以前 25,000 次播放同时结束要花四分钟以上。
- **成千上万人观看时，正在播放仍然很快。**以前查找谁在一起看时，会把每路播放与其他每路比较，并按名字列出每位同伴：10,000 路播放时需要四十秒，内存还要占用若干 GB。现在只在同一作品内比较播放，每路只显示几个名字和其他人数。
- 以前计算谁在一起看时，FinStats 每次启动、导入或看到播放结束，都会重写历史中每个分组的播放；现在只写入有变化的部分。查找哪些播放已经结束，不再随正在播放数量的平方变慢。
- **判断历史中是否已有某次播放改为走索引**，因此导入 150,000 次播放只需几秒钟，媒体库读取后的重新关联也改为逐个作品处理，而不是在占用数据库的同时读取每一次播放。
- **在全部时间范围内，播放洞察和概览更快了**：彼此独立的部分并行计算，并发图表每一刻钟查一次本地日期，而不是每次播放查一次，类型按作品计数。在 100 万次播放上：从 4.1 秒降到 2.4 秒，从 1.6 秒降到 1.1 秒。

### Stability
- **电视剧媒体库不再被当作被掏空的媒体库。**读取媒体库要经过两轮（先是所有项目，然后是只针对电影和剧集演职人员的较小一轮），而决定一次读取能否被信任、用来移除它没有看到的内容的检查，看的却是第二轮。在电视剧或音乐媒体库上，这两个数量相差甚远，因此检查拒绝了每一次读取并停止了 FinStats，安装重启后又重复同样的过程。从来没有任何内容被错误移除，但没有一次媒体库读取能够完成。如果你的剧集或音乐媒体库一直没有收进新作品，原因就在这里。
- 以前如果另一个写操作（例如正在刷新的播放）恰好发生在导入的第一次读取和第一次写入之间，导入可能因“database is locked”而失败。现在两个导入器在开始时就获取写锁，数据库日志也不再一直保持在有史以来最大一次导入的大小。
- **损坏、被截断、属于别人或只读的数据库文件会被立即拒绝**，并指出文件名、说明没有做任何更改，而不是默默等待 30 秒；绝不会写入其他程序的数据库。
- 中途中断的备份或更新前快照不再留下文件，这类文件以前可能在保留的三份快照中挤掉一份完好的快照。
- **在 FinStats 运行时覆盖地点数据库不再导致它崩溃**：FinStats 从该文件的一份私有副本读取。
- 每次都报告新设备 ID 的 Jellyfin 应用，可能让 FinStats 的内存在运行期间不断增长；现在五分钟没有出现的设备会被遗忘。
- 每个人最多保留 30 个登录会话；下次登录时，最早的会话会被退出。

### Fixed
- **作品改名后，同一个晚上不再被计算两次。**以前把历史重新关联到在 Jellyfin 中重新添加的作品时，可能把从追踪器导入的播放变成已有播放的重复项，因为本该发现它的检查在 ID 移动之前就运行了。现在凡是重新关联 ID 的地方都会再次运行该检查。只会移除导入的播放，绝不会移除 FinStats 自己记录的播放，移除了多少会记录在日志中。2.0 的首次启动会对整个历史清理一次已存在的重复项。
- **会话现在跟随此人在 Jellyfin 中的当前状态。**以前被 Jellyfin 降级的管理员在 30 天会话的剩余时间里仍保有 FinStats 的完整权限，在 Jellyfin 中被禁用或删除的人也保持登录。现在一旦 FinStats 读取 Jellyfin 的用户（每 15 分钟一次，或在设置中立即读取），他们就会失去访问权限，与 API 密钥一贯的做法相同。
- 登录时会把 Jellyfin 关于此人的信息写入 FinStats 的用户列表，因此导入的追踪器备份不再能在首次读取用户纠正之前让某人成为管理员。
- 即使两次读取用户发生在同一秒内，在 Jellyfin 中被删除的人也会被标记为已移除。
- **下载错误绝不会显示下载客户端的密码或索引器的 API 密钥**，Sonarr 和 Radarr 有可能在错误中引用它们。
- 媒体库读取期间重新关联到改名作品的播放，以前要等到下次重启才会检查是否属于一起观看；现在会立即检查。

## [1.6.0] - 2026-09-24

通知

### Added
- 设置下的**通知**卡片：添加一个通知目标，勾选它应该收到哪些消息，然后按测试。没有通知目标，就不会向任何地方发出请求。
- 四种通知目标：普通的 **Webhook**（JSON，格式见 `docs/api.md`，可选 `Authorization` 请求头）、**Discord**（通过频道 Webhook URL 发送嵌入消息）、**ntfy**（ntfy.sh 或你自建的服务，发往某个主题）以及 **Gotify**（你自己的服务器，使用应用令牌）。标题放在消息正文中，而不是请求头中。
- 十一种事件，各有一个勾选框：不可能的旅行、账户在新的国家出现、短时间内大量登录失败、任务失败、备份无法写入、某项服务停止响应（Jellyfin、Sonarr、Radarr 或 Seerr）以及它恢复响应、媒体库中的新作品（按剧集和日期合并，与仪表板的展示栏相同）、请求变为可观看，以及播放开始或结束。最后两种默认关闭。
- 请求变为可观看时，通知会写明作品、请求者以及他们等了多久。
- 个人通知目标：授予**接收通知**权限后，用户可以添加自己的通知目标，它只会收到此人本来就能看到的内容：自己的请求和警报始终可以，别人的需要*查看所有人的活动*权限，地址需要*查看网络详情*权限。个人通知目标必须指向公网地址；只有管理员可以把它指向内网。
- **包含 IP 地址和地点**，按通知目标设置，默认关闭：否则关于不可能的旅行的消息只会写出地点（“挪威奥斯陆和英国伦敦”）。
- 同一张卡片中的**最近发送**：发送了什么、发给哪个通知目标，以及发送失败时对方的应答。失败的消息会在大约一小时内重试四次，遇到限流的通知目标会等待。
- **FinStats 的地址**是一项管理员设置，通知中的链接由它构成。留空则消息不带链接。
- 服务器页面上的 Jellyfin 自身计划任务：用文字说明每个任务做什么，而不是只给出它在代码中的名字，并标明是否属于繁重的任务。正在运行的任务显示进度条、百分比和剩余时间；其他任务显示下次运行时间、上次运行时间以及上次是否顺利。Jellyfin 在自己的控制台中隐藏的任务也包括在内，FinStats 中没有任何东西能启动或停止任务。
- 任务的剩余时间根据其百分比实际推进的速率来估算，并以足够久之前、有参考意义的最近一次读数为基准，而不是整个运行过程的平均值，因此加速或减速的任务会按它当前的速度来描述。
- FinStats 出于其他原因已经在读取的任务列表（每 5 分钟一次的媒体库扫描检查、每 15 分钟一次的服务器详情）也用于同样的测量，因此运行了一小时的任务通常在页面打开时就已有估计时间。不会为此向 Jellyfin 额外发出任何请求。
- 尚未测得任何数据的运行中任务会显示 **ETA** 和循环的省略号，而不是数字；百分比半分钟没有变化的任务，旁边会显示“停在 68% 已 4 分钟”。没有测得的估计值，绝不用别的东西代替。
- 更新日志旁边列出每个版本：一键即可跳到任何版本，正在阅读的版本会被标出，在窄屏上它会变成更新日志上方的一排系列。

### Changed
- 更新日志不再折叠。每个系列都展开显示，通过版本列表来浏览，而不是一次只展开一组、要点击才能到达其他组。
- **设置 → 出站连接** 会在 Jellyfin 和服务连接旁边列出每个通知目标：它是什么、主机、是否已开启，以及上次接收消息的时间。
- 采集、历史或屏幕上的任何数字都没有变化。FinStats 仍然只*读取* Jellyfin、Sonarr、Radarr 和 Seerr 的数据。

WebSocket 会话跟踪

### Changed
- FinStats 从启动起就与 Jellyfin 保持一条连接，并以此获知播放情况。1.4.0 把它作为默认关闭的设置发布，以便在真实服务器上验证；现在它始终开启。播放、暂停和跳转与以前相同，由同样的代码计算。
- 没有播放时：FinStats 完全不向 Jellyfin 发出任何请求。没人观看的夜晚不会产生任何请求。
- 有内容在播放时：每秒读取一次会话列表。暂停、跳转或音轨切换的精确度由此而来，客户端不告而别时，播放也靠它来结束。
- 所有已加载的内容连续三次读数都处于暂停时：停止查询，改由连接来传递，而以前一部暂停的电影每秒都要问一遍同样的问题，每小时约 16 MB。继续播放或其他人开始播放，大约一秒内就会有响应，暂停的时间仍然绝不计入观看时长。
- 每次对外读取都请求压缩的应答并自行解压（Jellyfin、Sonarr、Radarr 和 Seerr 在被要求时都会压缩），这让两项最大的读取减少了一半以上：播放期间的会话列表和媒体库读取。地理位置数据库仍按其存储格式下载。
- 设置中的 Jellyfin 卡片会说明当前运行的是哪种方式（主动查询还是连接推送），实时指示点反映的是连接是否在传递数据，而不是当前处于哪种方式。
- 两者同一时间只运行一个：FinStats 主动查询时，会告诉 Jellyfin 停止推送，最后一个播放结束的那一刻再请它重新开始。连接始终保持打开。
- 对订阅毫无回应、但仍回应保活消息的 Jellyfin 会被信任：FinStats 会说明一次，在此期间自己读取会话列表，并保持订阅，直到第一次推送确认为止。“无法推送”和“被问到时正在重启”看起来一样，因此沉默绝不会被当作结论。
- 后备机制不变：连接关闭、变得沉默或者发现不支持这种方式时，下一轮就会退回按计时器查询，并不断重连，间隔为**有人观看时，检查间隔**和**没有播放时，检查间隔**。

### Added
- `GET /api/status` 上显示采集器正在做什么：它处于四种状态中的哪一种（`idle_socket`、`playing_poll`、`paused_socket`、`fallback`），连接是否打开并已订阅，查询频率，最近一分钟发出了多少次会话读取，以及上次变化的时间。从内存中作答（不发请求，不查数据库），不包含任何名字、标题或数量。
- 每一轮都会互相核对这些字段，持续存在的不一致会写入日志。
- 进程中所有会话读取都受同一个限流器约束：每秒最多 2 次，每分钟最多 70 次，超出的部分会被延迟、计数，并且每分钟最多记录一次日志。正常观看远低于这个上限。

### Fixed
- 实时更新真正取代了轮询。开启后，1.4.0 仍然每五秒请求一次会话列表，并每二十到四十秒重新打开一次连接，因为它根据最近一次收到列表的时间来判断连接状态，而 Jellyfin 只在内容*变化*时发送列表，其间什么都不发。现在连接是否存活取决于 Jellyfin 是否还在应答，大约每分钟用保活消息检查两次。
- FinStats 在两轮之间收到的会话列表以前会被丢弃，理由是一秒半后还会有另一份。现在它会被保留并使用。
- 设置中的**上次检查**以及出站连接卡片，在连接安静时不再过时：它们显示的是 Jellyfin 对保活消息的应答。

### Removed
- “设置 → 采集”中的**让 Jellyfin 推送正在播放的内容**设置，以及设置 API 中的 `live_socket`。
- 采集器状态中的 `socket_enabled`：不再有“已关闭”这种状态。
- 采集器状态中的 `last_reconcile_at`，由 `socket_live` 取代。
