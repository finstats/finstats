# 更新說明

FinStats 的所有變更，最新的在前。這個檔案會編譯進執行檔，也就是應用程式中
**更新說明**分頁所顯示的內容。

格式：`## [version] - date`，或者橫跨數天完成的版本寫成 `## [version] - first day to release day`，接著是
`### Added`、`### Changed`、`### Security`、`### Performance`、`### Stability`、`### Fixed` 或 `### Removed`
（新增、變更、安全性、效能、穩定性、修正、移除），每項變更一個項目。安全性是指可能被人濫用的地方，效能是指變得
更快或更輕量，穩定性是指不會再當機、停止、洩漏或遺失資料，修正是指原本給出錯誤答案的地方。`x.y.0` 版本在標題
下方有一行簡短的標題文字：應用程式會把它當成整個系列的標題。

## [2.3.1] - 2026-10-26 to 2026-10-30

### Security
- **設定精靈需要一次性代碼**：在完成設定之前，FinStats 每次啟動時都會把一組代碼寫入記錄（`docker logs finstats`），精靈在測試位址或設定任何東西之前都會要求輸入。否則，最先連上這個連接埠的人就能把 FinStats 指向自己的 Jellyfin 並成為它的管理員，或利用測試功能在網路上四處探查。
- **媒體庫存取跟隨 Jellyfin**：每個人只會看到 Jellyfin 開放給他的媒體庫，而且在其中只會看到 Jellyfin 依其分級上限、標籤和未分級規則為他列出的標題，範圍包括媒體庫頁面、搜尋、演職人員、圖片、最近新增、待看清單、即將推出、行事曆訂閱和新標題通知。以前每個已登入的人都能瀏覽所有媒體庫。
- 以前連結可能在某人登入後，立刻把他從歡迎畫面送到其他網站。現在只會前往 FinStats 自己的頁面。
- 伺服器記錄和洞察中的登入失敗，以前會把所有人的登入位址和活動提供給任何擁有 *查看伺服器* 的人。現在別人的記錄需要 *查看所有人的活動*，位址需要 *查看網路細節*，與其他地方相同。
- 個人通知目的地以前可能透過一個第二次查詢時回應不同的名稱連到區域網路。現在會連線到經過檢查的那個位址，更多永遠不會連到網際網路的位址範圍會被視為本機，家中自己的公開位址也會被拒絕，而無法查詢的名稱會以與本機名稱相同的說法被拒絕。
- 在會自行加上一行 `X-Forwarded-For` 的代理伺服器後方，或來自 IPv6 網路時，每次登入嘗試都可能來自新的位址，限制從未生效。現在一個 IPv6 /48 在五分鐘內有 50 次嘗試，限制表滿了時會拒絕新位址而不是忘掉舊位址，整個伺服器在每分鐘 60 次失敗時停止受理，而每個位址在每個時間範圍內的登入失敗只稽核一次。
- `FINSTATS_TRUST_PROXY` 指定哪些代理伺服器（位址或範圍）的 `X-Forwarded-For`、`X-Forwarded-Host` 和 `X-Forwarded-Proto` 可被採信，而 `1` 或 `true` 現在只採信迴路或私人網路上的對端。以前開啟時，任何對端都能自選位址；在代理伺服器後方不開啟時，十次錯誤猜測就會把所有人鎖在門外。
- 讀取使用者之後，對未知、已停用、已移除或未獲准進入 FinStats 的名稱，登入會不詢問 Jellyfin 就以密碼錯誤回覆，而且不會比 Jellyfin 本該回覆的時間更早。以前這些名稱可能鎖住 Jellyfin 帳號、繞過 Jellyfin 的遠端存取規則，或躲在 FinStats 的位址後面。
- 被 Jellyfin 限制在家用網路內的人（*允許遠端連線* 已關閉）只能從家用網路登入 FinStats，因為 Jellyfin 是依 FinStats 自己的位址來判斷這個開關；沒有說明某人是否停用的使用者讀取結果，會把他擋在門外。
- 只要登入的頁面使用 https，工作階段 cookie 就會標記為 Secure，即使在沒有表明這點的代理伺服器後方也一樣。
- 成功登入不再抵銷之前的猜測次數。在 https 下，工作階段 cookie 是 `__Host-` cookie，相鄰名稱上的網站無法取代它，也不會以其他名稱接受；登出會結束瀏覽器送出的每一個工作階段。
- 只有行事曆金鑰可以從網址開啟行事曆訂閱；其他任何金鑰都要放在標頭中。
- API 金鑰不再能授予權限、變更誰能進入或哪些內容公開、還原備份，或新增、變更、測試服務或通知目的地：這些都比金鑰存在得更久，因此需要已登入的瀏覽器。
- 每個回應都帶有 `Cross-Origin-Opener-Policy: same-origin` 和 `Permissions-Policy`，API 回應帶有 `Cross-Origin-Resource-Policy: same-origin`，除非另有說明都是 `no-store`，CSP 也不再允許 `blob:` 圖片。以前開啟 FinStats 的頁面之後可以把它的分頁變成自己的登入頁。
- 當 FinStats 知道連到它所用的協定時（受信任代理伺服器的 `X-Forwarded-Proto`，或公開位址），來自其他協定的寫入會被視為跨站而拒絕。
- `/auth/me`、標題頁面和媒體庫健康度以 Jellyfin 的公開位址連結到 Jellyfin；FinStats 自己讀取 Jellyfin 所用的位址只提供給管理員。
- 只會為 FinStats 擁有的項目向 Jellyfin 取得圖片，包括公開個人檔案的海報和卡片，因此無法用 ID 要求其他媒體庫的圖片。
- 下載佇列的錯誤訊息中也會遮蔽私人 tracker 的金鑰，同時依名稱和形式辨識；只有 *查看下載內容* 的人會得知哪個服務失敗以及如何失敗，但絕不會看到它的內部位址或重新導向的目標。
- 伺服器頁面只在具有 *查看所有人的活動* 時才顯示裝置的最後使用者，而未連結的媒體除了 *管理 FinStats* 之外也需要它。沒有它時，工作區段只計算自己的播放和串流，已移除的媒體庫依自己的播放列出，而等待中的 Tautulli 配線板也無法取消。
- 設定中只以主機名稱顯示公開位址服務，Jellyfin 的位址和資料資料夾只向管理員顯示，而媒體庫已失去的標題，只會依據讀者可以看到的播放來描述。
- 資料表不是一般資料表的 Tautulli 備份，可能讓其他所有寫入一直等待，直到 FinStats 重新啟動。現在這種檔案會被拒絕，SQLite 也會以防禦模式讀取備份。
- 超過 4 GB 的上傳會被拒絕，壓縮的 Tautulli 備份解壓縮時不會超過它宣稱的大小；兩者都可能塞滿 FinStats 自身資料庫所在的磁碟。
- 來自 Jellyfin、Sonarr、Radarr、Seerr、公開位址查詢或 GeoIP 下載的回應，讀取時不會超過允許的上限，以解壓縮後的大小計算。
- 以前任何 Jellyfin 使用者都能藉由回報同一標題的數千次短暫播放，讓 FinStats 停止為所有人記錄播放。現在判斷誰一起觀看只需一次處理，處理期間不會持有任何鎖定。
- 前後相接記錄的播放，或在一台又一台裝置上輪流播放的同一標題，不再把陌生人併入同一群組；對只能查看自己的人，只會告知與他自己的播放同時進行的人，以及同時進行了多久。
- 以前連結仍可能透過 `/.//` 這類路徑，在登入後把某人從歡迎畫面送到其他網站。
- 管理者不再能變更保留的備份數量或寫入頻率、合併時間範圍（現在最多一小時），或讀取使用者、活動記錄和備份的時間，而管理者的備份也絕不會擠掉管理員的備份；住家位址和移動規則需要與警示相同的權限，匯入歷史還需要 *查看所有人的活動*。
- 儲存的金鑰、權杖或密碼只會傳送到儲存時對應的伺服器；通知目的地只能在登入時建立或變更，絕不能用 API 金鑰。管理員可以停用或移除別人的個人目的地，但不能把它指向別處、關閉它的憑證檢查，或讀取它的 ntfy 主題或 Pushover 使用者金鑰。
- Discord 和 Slack 的 webhook 必須使用 `https`，因為它們的位址就是權杖。
- 大量登入失敗不再能掩蓋真正的登入或淹沒警示：不是帳號的名稱每十五分鐘只產生一則不點名任何人的通知，警示優先送出，Slack 和 Discord 以純文字顯示訊息內容，也不會提及任何人。
- 年度回顧的排名、容量、通知和公開的個人檔案透露的內容不會多於頁面：不向只能查看自己的人顯示排名或所有人時間中的占比，沒有 *查看所有人的活動* 時，忙碌時刻只以有三個以上串流的日子呈現，不向無法管理 FinStats 的人告知失敗的工作或連線，公開的個人檔案每天只變更一次。
- 含有產生欄位的 Tautulli 備份會被拒絕；匯入的播放只有在媒體庫已有其標題後才會取得圖片。
- 還原絕不會讓 FinStats 比現在更開放：只在要求時才還原設定，登入、權限和公開個人檔案會變成此安裝與備份都允許的範圍，公開位址維持此安裝自己的。`finstats restore <file>` 與頁面一樣只還原歷史，加上 `--with-settings` 才會連設定一起還原。
- 只還原歷史時不再帶回住家位址、已靜音的警示、冒充此安裝自身的稽核項目，或媒體庫中沒有的已定位標題；任何還原都不會帶回日期早於 1990 年或晚於明天的播放、記錄列或裝置。還原的播放無論聲稱來自哪裡都算作匯入，因此重新啟動後絕不會接續它。
- 資料資料夾只屬於 FinStats 自己的使用者（0700，其中的檔案 0600，映像檔中為 `umask 077`）。FinStats 拒絕以 root 身分在其他使用者擁有的資料資料夾上執行，並指出該使用的 `docker exec -u`；進入點腳本只變更該資料夾和 FinStats 自身項目的擁有者。
- 目的地的名稱不能包含控制字元，裝置、人員或標題的名稱也不再能在記錄中偽造一行。
- 連結的路由參數不再能連到其頁面以外的其他 API 路徑，而 FinUI 的元素建構器只在位址為 http(s) 或相對位址時才設定位址，絕不設定 `srcdoc`。
- 搜尋、公開的個人檔案和手動啟動的工作不再能讓 FinStats 忙不過來：搜尋最多 200 個字元，個人檔案依語言分別保存，卡片在短佇列中等待，工作、位址查詢、位置資料庫下載和測試訊息無論以何種方式要求都有啟動頻率限制，測試訊息依傳送者計算。取得位置資料庫也需要與閱讀安全性頁面相同的權限。
- 請求本文在前 15 秒過後必須持續送達，沒人讀取的回應在 30 秒後放棄，一個公開位址最多保持 64 個連線，受信任的代理即使使用公開位址也不受此限，本機或私人網路上的位址同樣不受此限。幾百個從不傳送本文的請求曾能讓 FinStats 無法回應任何人。
- 郵件伺服器的回應最多只讀到任何回應都不會超過的量（整封信 1 MB），測試訊息在佇列訊息允許的時間後停止。一個從不結束一行的伺服器曾能讓 FinStats 佔用越來越多的記憶體，直到它被停止。
- 媒體庫讀取以讀取所存的標題為準，而不是匯入帶來的標題；已讀取過的媒體庫中的 Jellystat 標題以已移除的狀態匯入。匯入虛構的標題曾能讓每次媒體庫讀取都在每次啟動時停止 FinStats。
- 全伺服器每分鐘 60 次登入失敗的上限只計算交給 Jellyfin 的嘗試，包括仍在等待其回答的嘗試。FinStats 自己拒絕的名字曾讓任何擁有幾個位址的人阻止所有人登入，而同時送出的大量猜測都會到達 Jellyfin。
- 被 Jellyfin 限制在家庭網路中的人，在每個請求中（包括其工作階段和金鑰）都受此限制，而不只在登入時；家是私人網路或查詢到的家庭公共位址，從不是手動填寫為家的位址；在 `FINSTATS_TRUST_PROXY` 未列出的代理之後，此人會被拒於門外。帶出家門的 Cookie 或金鑰曾能在任何地方打開一切，管理者也曾能為自己選定的位址打開家門。
- API 金鑰再也不能關掉會發現它被濫用的東西，或能撤銷它所做之事的備份：保留多少備份及多久一次、合併時間窗、家庭位址和出行規則、使用者、活動日誌和備份的排程、靜音或解決所有警報、把備份移入垃圾桶，或刪除通知目標。每一項在金鑰被撤銷後都仍然有效。
- Sonarr 和 Radarr 的海報以及想看清單的下一集也遵循媒體庫存取權限：Jellyfin 對某人隱藏的影集，對他既沒有海報也沒有日期。逐個數服務的 ID 曾能看出哪些隱藏的影集即將到來，清單也曾說出隱藏影集的下一集。
- 年度回顧的「一起看」章節與「一起看」頁面一樣，只列出與你同時播放的人。透過別人加入的群組曾列出從未與你一起看過的人。
- Jellystat 或 Streamystats 匯入會先讀完整個檔案，再取得資料庫的寫入鎖，然後只寫入保留下來的列。在鎖內讀取時，一個只有少量真實列、其餘是數 GB 任意內容的檔案，曾讓其他所有寫入（包括播放和登入）一直等待。
- 還原時每人只保留一條權限，人數不超過一個家庭的許多倍，檢查稽核記錄是否重複時也不再重讀剛寫入的每一條。精心構造的備份曾能在還原過程中越來越久地佔用記憶體和資料庫寫入鎖。
- 連同設定一起還原時，只有在本安裝也開啟的情況下才會開啟公共位址查詢和位置資料庫下載，且保留的備份數量和寫入頻率絕不少於本安裝。一個只保留一份的備份曾能讓下一次執行刪除其他所有備份。
- 任何磁碟都裝不下的檔案大小會被視為沒有大小，而且大小的相加方式保證任何總和都不會溢位。一個匯入的大小曾讓媒體庫頁面永久報錯。
- 一旦 FinStats 知道自己經由 https 存取（請求送往其 https 公共位址，或受信任的代理這樣說明），工作階段只從 `__Host-` Cookie 中讀取；在那裡，每個新工作階段都是 https 工作階段。經由什麼都不說明的代理、不帶 `Origin` 送出的登入曾會產生一般工作階段，相鄰網站可以把它塞進別人的瀏覽器。
- 映像建置時每個 GitHub 動作都固定到某個提交，兩個基礎映像固定到摘要，只有 Dependabot 會移動這些固定點；發行版本建置時不使用共享的建置快取。別人動作的標籤一旦被移動，曾可能把任意映像當作 FinStats 發佈。
- 依訪客自己的外觀繪製的 FinUI 樣式表只能由 FinStats 自己的頁面載入。同一主機其他連接埠上的頁面曾能從中讀出訪客是否已登入以及選了哪個預設。
- 每次被拒絕的登入，無論是 FinStats 還是 Jellyfin 拒絕，都在從送出時算起的同一時刻回應；名字的比對不分大小寫，A 到 Z 以外的字母也一樣。拒絕來得多快曾能透露哪些名字是真實使用者，輸入 `åse` 的「Åse」也曾在未詢問 Jellyfin 的情況下被拒。
- 下載錯誤現在會向非管理員隱藏用戶端位址。先前，能檢視佇列的人可以看到內部主機、連接埠和路徑。
- 以原子操作執行金鑰和通知目標的數量限制。先前，並行請求可能超出這些限制。

### Performance
- 公開的個人檔案最多每分鐘計算一次，而不是為上面的每張圖片和卡片重新計算。
- 無論開始多少次播放，同一個人的歷史一次只會進行一次安全警示掃描。
- 登入或登出、撤銷金鑰或變更某個人的授權時，只會要求與它相關的即時連線重新檢查。
- Tautulli 配線板只讀取一次歷史，而不是每個 Plex 使用者讀取一次。
- 快取中沒有的圖片由一個要求取得，其他要求等待；來源未能提供的圖片在 30 秒內不會再次要求。
- 網頁介面的檔案只用 gzip 壓縮一次並保存下來，字型也不再重複壓縮。

### Stability
- 備份檔名已被占用時會嘗試其他名稱，不會覆寫已完成的備份或刪除其他匯出的新暫存檔。
- Jellystat 舊格式的備份改為逐行讀取，而不是一次全部讀入；比任何備份中的行都長的一行會被拒絕。
- 同時進行的兩個 Tautulli 上傳不再寫入同一個檔案。
- 遠超過媒體庫標題清單或媒體庫健康度結尾的頁碼會是空白頁，而不是錯誤。
- 上傳中斷的匯入或還原，不再讓其他所有匯入和還原在重新啟動前都遭到拒絕，而它和在開始前就被放棄的匯入都不會留下檔案。
- 備份中的單一行最多讀取 8 MB，而且一次只接收一個 Tautulli 備份。
- 一次播放最多保留 2,000 個事件，匯入會略過不是在 1990 年到明天之間開始並結束的播放。
- 一個遠小於零的集數不再讓每次媒體庫讀取停住：媒體庫健康度（包括其摘要）、容量、重新連結和定位在相加與比較數字時不會溢位繞回，而發行版本會檢查溢位，因此任何遺漏只會讓一個工作停止，而不是陷入迴圈。
- 季數、集數或結束集數只在 Jellyfin 能容納的範圍內（0 到 2,147,483,647）保留，無論來自 Jellyfin、Jellystat 還是 Tautulli。
- ID 重複的 Tautulli 備份會被拒絕，因為同一個 ID 下幾 MB 的資料列就能耗盡處理程序的記憶體；備份以不可變方式開啟，不會留下 `-wal` 或 `-shm`。
- 連線必須在 15 秒內送出要求，同時最多服務 512 個：幾百個半開的通訊端就曾讓 FinStats 離線。即時通道上的訊框限制為 4 KB。
- 來自 Sonarr、Radarr 或 Seerr 的幾 KB 資料不再能變成幾 GB 的記憶體：清單只保留 FinStats 會讀取的部分。
- 從不回應的通知目的地只會拖慢它自己：各目的地同時傳送，持續逾時的目的地會被擱置十分鐘。
- 佇列的剩餘時間和總速度、還原的播放中的數字，以及播放離開垃圾桶的日期，不再會溢位。
- 還原在取得寫入鎖定之前先讀完整個檔案，拒絕解壓縮後遠大於其大小的檔案，並分批寫入，因此收集器在此期間會繼續記錄。
- 備份以 UTC 命名，絕不覆寫既有檔案，而且只清理 FinStats 自己的更新前副本。
- 日期在未來的伺服器記錄列不再阻止讀取活動記錄：會從其最新的、不在未來的那一列開始讀取。
- 同時到達某個公開連結的要求只會計算一次回應，而它的卡片在獨立的通道中繪製，因此持有連結的人不再能讓擁有者的年度回顧卡片回應 503。
- Jellyfin 媒體庫清單中缺少的媒體庫，其播放記錄會等待兩天，才會移到另一個媒體庫中同一標題的副本上。一次漏掉某個媒體庫的清單曾立即移走這些記錄，媒體庫回來後也沒有移回。
- Jellyfin 回報的磁碟大小超出任何數字的容量時，不再導致每次讀取伺服器詳情都失敗。
- 當頁面重複且沒有新 ID 時，停止從 Jellyfin 讀取。

### Fixed
- 某個帳號的登入失敗在每個時間範圍內只產生一則警告，到二十次時升級為警示；只有完整輸入的名稱才會計入該帳號（「x alice」不再計入 alice）。
- Discord 和 Slack 訊息先跳脫再截斷：滿是 Markdown 的裝置名稱曾讓 Discord 拒絕每一則提到它的警示。
- 個人目的地可以使用公開的 IPv6 位址。
- 在自行負責登入的代理伺服器後方（nginx `auth_basic`），FinStats 的 cookie 不再被拒絕。
- 包含 `{{url}}` 的顯示名稱會在公開頁面的預覽中照原樣顯示。
- 要求 9999 年的回顧時顯示預設年份，而不是報錯。
- 開啟期間權限被收回又被恢復的即時頁面，無需重新載入即可再次保持最新。

### Removed
- **Synnmørsk** 不再是 FinStats 的語言之一：選擇過它的瀏覽器將顯示其所依據的書面語新挪威語（Nynorsk）。

## [2.3.0] - 2026-10-07 to 2026-10-26

容量、即時通道、簡易模式和多語言

### Added
- **語言**：FinStats 支援 23 種語言。英式英文、美式英文、書面挪威文（Bokmål）和新挪威文（Nynorsk）由維護者親自撰寫與檢查；丹麥文、德文、西班牙文、芬蘭文、法文、印地文、冰島文、義大利文、日文、韓文、荷蘭文、波蘭文、葡萄牙文（巴西）、俄文、瑞典文、土耳其文、烏克蘭文和中文（簡體與繁體）是這裡沒有人檢查過的翻譯，尚未翻譯的內容會以英文顯示。兩種版面的每個頁面、公開個人檔案、更新說明，以及伺服器以文字回覆的內容（錯誤訊息、年度回顧的卡片、某個 Jellyfin 工作的作用），都會使用在「設定 → 外觀 → 語言」中選擇的語言，每個瀏覽器各自設定；選擇之前，由瀏覽器本身的語言決定。數字、日期、單位和清單都依該語言的慣例書寫。指令碼可以用 `Accept-Language` 指定語言。
- **簡易模式**：為從 Plex 轉過來的人準備的第二種版面，排版方式就像經典的 Plex 統計伺服器。頂端一列取代選單，只保留統計頁面：首頁、媒體庫、使用者、記錄、圖表和設定，另有一個齒輪可前往你的個人檔案、設定、更新說明、佈景主題和登出。在「設定 → 外觀 → 版面」中依瀏覽器各自選擇。它只載入 FinStats 屬於自己的那一半，所以啟動更快；年度回顧、一起看、即將上架、安全性和伺服器頁面留在 FinStats 版面中。它使用 FinStats 自己的配色，淺色和深色皆然，畫面上沒有任何東西會動。
- **簡易模式的首頁**：正在播放的內容，每個串流一張卡片（播放方式、在家或在外、何時結束）；觀看統計以排名卡片呈現，依過去 N 天的播放次數或時長排序；每個媒體庫有哪些內容，以及最近新增了什麼。
- **簡易模式的圖表**：依媒體類型區分的播放（逐日、依星期與時段、前十名的應用程式和使用者）、依播放方式區分的播放（逐日、每天同時最多的串流數、檔案本身與實際傳送的解析度、應用程式和使用者），以及逐月統計，都可依播放次數或時長檢視，對象是所有人或所選的人。
- **簡易模式的媒體庫、使用者和作品**：列出每個媒體庫和每個人的表格，包含最後播放了什麼、在什麼上播放、從哪裡播放（位址需要 *查看網路細節*），以及每個媒體庫、每個人、每部作品各自的頁面，附上它的數據和專屬的播放記錄。
- 給指令碼使用：`/api/stats/split`（依應用程式、使用者、解析度、日或月區分的播放，再依媒體類型或播放方式細分）；依不同觀眾人數排序的排行榜（`sort=users`）；只列出算作已觀看的播放的活動（`watched=1`）；只計算指定部分的洞察（`parts=`）；高峰拆成轉碼、直接串流和直接播放，也可逐日查看；每個媒體庫有哪些內容、最後播放了什麼；依類型區分的最近新增（`kind=`）；依媒體類型區分的熱度圖；某人的最後一次播放；串流是否從家中播放。
- **即時通道**：控制台、即將上架的下載和狀態列，透過每個分頁一條 WebSocket（`/api/live`）保持最新，正在播放和正在下載的內容會在變化的當下更新在畫面上，不必等到下一次查詢。如果反向代理不轉送 WebSocket 升級，或連線無聲無息地中斷，頁面會像以前一樣每隔幾秒查詢一次。`/api/now-playing`、`/api/downloads` 和 `/api/summary` 維持不變，供指令碼使用。
- **伺服器 → 容量**：根據 FinStats 看過的情況，判斷這台伺服器撐不撐得住。記錄中以及過去 90 天最忙碌的時刻：同時有多少個串流，其中有多少個的畫面以硬體轉碼、不用硬體轉碼，或沒有說明（從 Tautulli 匯入的記錄屬於 Plex，因此不列入）。媒體庫所在的每顆磁碟，以及 Jellyfin 過去六個月新增的內容以多快的速度填滿它（最近才開始填入的磁碟，從第一個檔案之後一個月起算，因為第一個月就是在填入），而在 Jellyfin 10.11 以上版本會回報可用空間時，算出照這個速度還能撐多久。FinStats 從不說伺服器能承受多少個串流。
- **匯出 .ics**（即將上架 → 即將推出）：把你篩選後的清單下載成行事曆檔案，匯入一次即可。它不會自動更新；從「設定 → API 金鑰」取得的行事曆金鑰，仍可提供會自動更新的行事曆。
- **值得一看**：當 Jellyfin 在 90 天內回報的每次轉碼都沒有使用硬體加速、而轉碼又很常見時，當 Jellyfin 的媒體庫掃描占了四分之一以上的時間時，以及當某顆磁碟的剩餘空間撐不到六個月時，容量頁面會提醒你。每一則都附上數字，也可以像媒體庫健康度的發現一樣擱置。
- **你的媒體庫由什麼組成**現在可以限定為一個或多個媒體庫，在媒體庫頁面和每個媒體庫自己的頁面上都可以（`library_id=a,b`）。
- **日期與時間格式**（設定 → 外觀）：日期可寫成 31.01.2026, 31/01/2026, 31-01-2026, 01/31/2026, 2026-01-31, 2026.01.31 或 2026/01/31，時間可用 24 或 12 小時制，可加或不加前導零，也可都依語言自己的寫法。保存在此瀏覽器中。
- **歡迎頁**：有人第一次登入時（無論在哪個瀏覽器），以及設定結束時，FinStats 會詢問語言、日期與時間格式以及版面，每項都附一張圖。略過會保留英式英文、31/01/2026、13:05 和 FinStats。

### Changed
- 頁面內的標誌是名稱旁的單純圖形，不論預設組合選用哪種字型，都以 Inter 排版；單獨出現時（網站圖示）則保留圓角方塊。
- 在 Jellyfin 有說明的情況下，以軟體轉碼的播放會如實記錄；以前它看起來就和來自不提供這項資訊的伺服器的播放一樣。頁面上兩者仍都稱為「軟體」。
- 更新時，除了資料庫遷移之外，現在還會針對舊版 FinStats 寫入的資料庫，執行各版本需要做的處理，每項只執行一次，從最舊的版本開始。2.3.0 的處理是在第一次啟動時讀取伺服器的詳細資訊，讓容量頁面立即可用。

### Performance
- **開著不動的頁面不再發出任何請求**：控制台為了保持最新，每分鐘發出 30 個請求，即將上架的下載則是 18 個；有了即時通道，兩者都是零。不論開了多少分頁，FinStats 向 Jellyfin、Sonarr 和 Radarr 要求的都不比以前多，隱藏的分頁也仍會讓下載佇列放慢讀取頻率。
- 使用者頁面只讀取那個人的播放：以前他的總計和最後一次播放，是先就伺服器上的每一次播放算出來，再縮小到他身上，在一百萬次播放上約需四秒。
- 媒體庫頁面只讀取那個媒體庫的作品和播放；以前會計算每個媒體庫的資料再只留下一個：在一百萬次播放上，時間只剩三分之一。
- 當 Jellyfin 的時鐘比 FinStats 快時，*Jellyfin 媒體庫掃描之後* 會每分鐘重新讀取整個媒體庫，直到時間差過去為止；現在每次掃描只跟進一次。
- 無法開啟的 GeoIP 檔案會每十五分鐘重新複製一次（一百 MB 以上），並重新定位每一個位址；現在只有在檔案變更後才會再試。
- 指標在連結上停留後，媒體庫健康度會立即開啟：先行擷取的內容原本存放在頁面從來不會去找的地方。

### Stability
- 以前更新在資料庫遷移執行之後失敗，又被 Docker 立刻重新啟動時，每次啟動都會為只更新了一半的資料庫建立一份新副本，三次啟動之後，前一版唯一能開啟的那份副本就被清掉了。現在會保留更新之前的那份副本。
- 以前，讀取媒體庫期間在 Jellyfin 中刪除的作品（例如被 Radarr 替換的檔案），可能讓讀取漏掉另一部其實還在的作品並將它標記為已移除，它的播放接著可能被移到另一份副本上。現在讀取時沒看到的項目，會先以 ID 查詢確認。
- 以前還原在檔案重新命名或升級之前建立的備份時，從那之後已移到新檔案上的每一次播放，都會被再還原一次，從此重複計算。
- Seerr 回應中 FinStats 讀不懂的請求（例如 Seerr 更新後改了名稱的欄位），以前會在每天的完整讀取時被標記為已移除。
- 以前遇到錯誤的工作會一直停在「執行中」，在 FinStats 重新啟動之前，任何觸發條件都不會再啟動它；現在它會以失敗結束。
- 損壞的 Tautulli zip 以前會讓上傳在刪除檔案之前就中止，而這個檔案含有每位 Plex 使用者的權杖，要等到六小時一次的清理才會刪除。
- 以前在檔案傳送途中被中止的匯入或還原，會把檔案永久留在資料資料夾中，連同裡面的位址；現在會在下次啟動時刪除。
- 以前圖片在寫入快取時可能只寫了一半就被送出，瀏覽器接著會一直保留那個狀態。
- 已撤銷的 API 金鑰以前會永遠保留，不論建立和撤銷了多少把。
- 讀取某人的已看與收藏標記時，若回傳為空或無法讀取，會把它們全部清除，直到下一次讀取；現在會像媒體庫的空讀取一樣被拒絕。
- 一集的結束編號若是任何一集都不可能有的（那裡寫了一個日期），在讀取媒體庫後可能讓媒體庫健康度一直忙個不停。

- 計數圖表的座標軸可能標成 0、3、5、8、10，甚至 0、0、1、1、1：步長 2.5 被四捨五入後顯示。現在計數按整數步長遞增。

- 以前按下「返回」後，對話方塊仍停留在頁面上，在關閉之前頁面無法捲動。
- 稽核記錄以前以 ID 顯示八種項目（恢復的播放或備份、清空垃圾桶、公開個人檔案、外觀變更），「詳細資訊」中什麼都沒有。

- 控制台上的 *一起觀看* 以前會把同時選取的多個人當成同一個人。

- 在安全性頁面上，沒有位置的位址統計的是所有人全部時間的播放，不論頁面限定到哪個人和哪段時間。

- **伺服器 → 媒體庫健康度**：FinStats 把每個檔案與相鄰的檔案比較，列出突出的地方，每一項都附上背後的數字。它只回報，不會在 Jellyfin 中變更、刪除或重新掃描任何東西。
- **缺集**：一季中兩個檔案之間缺少的單集（「第 2 季：第 3 集和第 6 集之間缺少第 4 集和第 5 集」）。一個檔案包含兩集時算作兩集；特別篇和一季的結尾不列入。
- **不一致的季**：解析度、HDR 或編解碼器與同一部影集其他季不同的季；以及**不一致的單集**：與同季其他集不同的檔案，例如 1080p 的一季中有一集是 SD。解析度依寬度或高度判斷，因此裁切成 1920×800 的電影算 1080p。
- **重複和多版本**：同一部電影或同一集出現兩次，依據的是待看清單和即將上架原本就使用的提供者 ID。同一解析度的兩份副本，會顯示被重複占用的空間；4K 副本與 1080p 副本並存，會列為兩個版本，絕不算作浪費。
- **位元速率過低**：位元速率遠低於該解析度和編解碼器通常所需（「4K HEVC 只有 1.1 Mbps」）；一季中位元速率過低的單集合為一項發現。
- **中斷的配音**：某種音訊語言在某些季的每一集都有，在其他季卻一集都沒有。
- **從未識別**：Jellyfin 比對時沒有找到任何 TMDB、TVDB 或 IMDb ID 的電影和影集。
- **忽略**刻意保持原樣的發現，並附上備註。檔案變更時它會自動回來。可以管理 FinStats 且能查看伺服器的人才能忽略；忽略會記錄在稽核記錄中，也包含在備份裡。
- 媒體庫頁面會說明那裡有多少項目值得查看，並帶你前往。
- **FinUI** 是構成 FinStats 的元件，現在是獨立的專案（`github.com/finstats/finui`）：在 `finui.finstats.no` 可以看到每個按鈕、卡片和控制項的每種狀態及兩種佈景主題，**FinUI create** 則能即時調整顏色、圓角、密度等，再用一道指令帶回家。**設定 → 系統**有連結通往那裡。
- **設定 → 外觀**：每個人都能以 FinUI 預設組合的代碼，選擇 FinStats 在自己眼中的樣子：基礎色、強調色、圖表顏色、對比、圓角、密度、框線、卡片、按鈕、欄位、表格、醒目提示、動態效果、圖示、選單、所有內容後方的頁面、焦點框、標題的排法，以及內文、標題和數字的字型。你的選擇只屬於你；它會顯示代碼的意思，並連到 FinUI create 讓你修改。
- **樣式**：在 FinUI create 中，一次選擇就能從十一種完整外觀之一開始，它產生的代碼可以貼進「設定 → 外觀」。這些樣式是 Washi（FinStats 的出廠樣式）、Studio、Noir、Matinee、Console、Pastille、Ledger、Gazette、Arcade、Canopy 和 Harbour。FinStats 本身只提供一種外觀，不提供樣式清單。
- **會動的圖示**：連結、按鈕或分頁中的每個圖示，被指向時都會做一次自己的動作（重新整理會轉一圈、下載的箭頭落進托盤、垃圾桶掀起蓋子），而按下的重新整理會一直轉，直到回應送達。開啟減少動態效果時，以及動態效果設為關閉時，都保持靜止。
- **動態效果，由 FinMotion 提供**：FinUI 的元件現在會動：開關的圓鈕被甩到另一邊、分頁的底線一點一點移到下一個分頁、被拒絕的欄位會搖頭、複製時一筆畫出勾號、通知像一手牌般疊起，被指向時展開成扇形、手機的面板被拉動時像橡皮筋一樣有彈性、排序後表格的列會移到自己的位置、變動的數字像里程表般滾動，圖表在第一次出現時會自己畫出來。這一切都依循「設定 → 外觀」的動態效果選項，開啟減少動態效果時保持靜止。FinMotion 是獨立的專案（`github.com/finstats/finmotion`），疊加在 FinUI 之上。

- **替換的檔案不算「現在已在伺服器上」**：某人待看清單上的電影檔案升級後，不會再通知他這部電影剛到。

## [2.0.4] - 2026-09-29

### Added
- **工作排程，跟 Jellyfin 的做法一樣**：FinStats 自動執行的每項工作都有觸發條件（每天的某個時間、每週的某一天、固定間隔、啟動時，或 Jellyfin 媒體庫掃描之後），每個都可以設定時間上限。點選工作即可查看和變更它的排程；*新增觸發條件* 會開啟與 Jellyfin 相同的對話方塊。

- **中繼資料變更**：FinStats 每小時讀取 Jellyfin 自上次查看以來儲存的內容（名稱、簡介、類型、分級、演職人員、檔案詳細資訊和圖片），所以在 Jellyfin 中的編輯不必等媒體庫掃描就會出現。

### Changed
- **佈景主題是有三段的開關**：淺色 · 跟隨裝置 · 深色，取代原本循環切換的按鈕：點選其中三分之一、拖曳圓鈕或使用方向鍵。圓鈕上顯示所選項目的圖示，變更時會以動畫移入。
- **登出位於設定 → 帳號**，那裡會顯示這裡登入的是誰；側邊欄保留佈景主題開關。
- **舊的排程設定現在變成觸發條件**：*跟隨 Jellyfin 的媒體庫掃描* 及其備援間隔、*每 N 天備份一次* 以及 GeoIP 的 *保持資料庫最新* 開關，都已變成各自工作上對應的觸發條件，保留你原本的數值。收集、備份和安全性改為連結到排程。
- 啟動時不再重新執行每一項工作：每項工作上次完成的時間會被保留。
- 還沒有估計值的 Jellyfin 工作會顯示「還剩約 …」，點點在之後會出現時間的位置循環，而不是「ETA…」。

### Performance
- **安全性地圖不再卡頓**：拖曳和縮放時移動的是已經畫好的地圖，手勢停下後才重畫一次，而「正在播放」的脈動在沒人操作時也不會再讓整張地圖每秒重繪 120 次。在一台慢的電腦上，拖曳從每秒 34 個影格提升到 60 個。

### Fixed
- **在 Jellyfin 中替換的海報或人像會出現在 FinStats 中**：圖片原本在伺服器上快取一週，在瀏覽器中再快取一週，不管 Jellyfin 之後換成了什麼。現在以 Jellyfin 的圖片標籤快取，所以新圖片就是新檔案，瀏覽器每次顯示時也會確認自己的副本是否最新。替換人像只會重新儲存該人物，所以中繼資料變更也會讀取人物。
- **伺服器 → 工作在頁面開啟時就顯示估計值**：剩餘時間原本只根據頁面開著時自己讀到的數值計算，所以每次造訪都從「ETA…」開始，直到它看到百分比動起來。現在 FinStats 會自己為執行中的 Jellyfin 工作計時，執行期間每 10 秒一次，頁面直接取得估計值。Jellyfin 從頭到尾回報 0% 的工作（媒體庫掃描的第一階段）會一直顯示點點，直到它開始動：不做任何猜測。
- **地圖的提示會出現在點上**：在 Firefox 中，「正在播放」點的提示可能出現在很遠的地方，而點重疊時（有人在家播放），顯示哪個提示取決於一個像素。現在一個提示會列出指標下的所有內容。
- **狀態列只有一種滑鼠懸停樣式**：每個連結（串流、原始碼、版本）都以同樣的小方框亮起，項目之間的點也會置中於間隙中。以前懸停在版本上時，連它前面的點和間隙也會一起亮起。
- **檔案路徑占滿卡片的整個寬度**：在作品的「檔案」卡片上，以及伺服器頁面上 Jellyfin 的資料夾，路徑原本被擠進一個窄窄的格子，旁邊空著，卻往下排了九行。
- 正在淡出的對話方塊不會再吃掉對下方頁面的點選。

## [2.0.2] - 2026-09-28

### Security
- 在代理伺服器後方時，登入次數限制以前計算的是第一個 `X-Forwarded-For` 位址，而那是用戶端自己送出的：每次嘗試換一個捏造的位址，限制就永遠不會生效。現在計算的是最後一個，也就是代理伺服器寫入的那個。
- *包含 IP 位址和地點* 以前會把位址傳送到擁有者沒有 *查看網路細節* 的個人目的地，而任何頁面都不會讓他看到這些位址。現在別人的登入失敗還需要 *查看伺服器*，與安全性頁面相同。

### Stability
- **停止執行的要求絕不會遺失**：以前在啟動後最初的時刻，伺服器開始監聽之前，如果媒體庫讀取被拒絕，這個拒絕只會被記下，FinStats 會繼續執行，而不是停止。
- **以 FinStats 讀不懂的格式回應的 Jellyfin 會被拒絕**，而不是被相信：每位使用者或某個媒體庫的每部作品，都以它不認得的鍵名送來（`id` 而不是 `Id`）時，以前會以完整的數量通過防護，接著被標記為已移除。
- **播放的結束絕不會被丟棄**：當資料庫忙碌到超過等待時間時（例如被匯入占住），在那一刻結束的播放以前會一直被標記為播放中，直到下次重新啟動。現在會在下一輪寫入。
- **還原時讀不懂的設定會保持不動**：以前設定已不符合這個版本的備份，在還原時會重設每一項設定：合併時間範圍、權限、家用位址、排程。
- **名稱或作品名稱中的控制字元不會再讓卡片壞掉**：以前個人檔案卡片、顯示該作品的每張故事卡片，以及它們的 ZIP，都會回應錯誤。

### Fixed
- **在 Jellyfin 中被停用或刪除的人不會再收到通知**：他們的個人目的地原本會繼續收到舊權限允許的所有內容。
- **排隊中的通知在傳送前會重新確認**：已關閉的目的地，或已失去某項權限的擁有者，原本仍會收到等待重試的內容。
- **一直回應 `Retry-After` 的目的地會被放棄**，和其他目的地一樣在嘗試五次之後，而不是持續重試三十天。
- **使用者頁面上的裝置 ID** 只在擁有 *查看網路細節* 時顯示，與其他地方相同。
- **公開的年度回顧所有內容都延遲一天**：它的看完和放棄的影集以前會跟著每一次播放更新，所以在放棄的影集上按下播放，幾秒內就會改變公開頁面。
- **一集被看過時，請求的影集就算已觀看**：每部請求的影集原本在「請求」章節和「請求」卡片上都顯示為從未觀看。
- **年度回顧的「有人陪伴」章節不包含電視直播**，與這一年的其他部分相同：以前一起開著的頻道可能變成第一名的作品，比例也可能超過 100%。
- **「最近 12 個月」的「每一天」卡片結束於最新的一天**：方格原本會漏掉最近的三、四週。
- **影集的新單集每晚只宣布一次**：以前在 UTC 以東或以西的伺服器上，橫跨 UTC 午夜的單集會被宣布兩次。
- **連接 Seerr 時不會把舊的請求宣布為可以觀看**：以前第一次讀取時就已經可以觀看、又沒有其他時間記錄的請求，會被當成在那一刻才到。
- **在 Jellyfin 中刪除的媒體庫，其作品會一併移除**：它們原本會留在搜尋、最近新增和總計中。
- **重新封裝（remux）會維持直接串流**，即使某次讀取暫時失去轉碼詳細資訊（例如跳轉時），而不是在剩下的播放中都變成轉碼。
- **「Jellyfin 無法連線」表示連續讀取失敗**：在透過 socket 閒置的伺服器上，相隔數天的零星逾時原本也會累積成這個結果。
- **Streamystats 匯入會在自己的卡片上顯示進度**，而不是蓋在 Jellystat 匯入的上次結果上。
- **主機名稱以「web」開頭的位址**（`http://web:8096`）會被當成主機名稱讀取，而不是被當成 Jellyfin 網頁用戶端的路徑而截斷。
- **佇列錯誤會遮蔽位址中的整段登入資訊**，即使密碼中含有斜線。

- **可分享的卡片**：每個公開的個人檔案都附有 1200×630 的圖片，包括個人檔案和這一年的，貼上連結時 Discord、Signal、Mastodon 等會顯示它，也可以下載後發布。在伺服器上依頁面顯示的內容繪製，不多不少。
- **可以收回的連結**：22 個隨機字元，按一下就能重設；舊連結之後的回應會和從未存在過的連結一模一樣。
- **在管理員允許之前，公開個人檔案都是關閉的**：整台伺服器一個開關、一份誰公開了什麼的清單，以及下架個人檔案的方法。公開、變更、重設和下架都會記錄在稽核記錄中，而金鑰無法讓任何東西公開。
- **一起看**，自成一個頁面：誰和誰一起看、看了多少，以及這些如何變化。共同觀看的時間、晚上數和有人陪伴的觀看時間比例，各自與前一個時間範圍比較；每天或每週有人陪伴與獨自觀看的時數；每一對人的晚上數、共同時間、最後一起看的時間以及最常一起看什麼；最常一起看的作品；最近的晚上；以及，給可以查看所有人的人：每個人獨自觀看與有人陪伴的時間對照。
- 每一對都算數：三個人的晚上會計入其中的三對，以前卡片只計算完全相同的一組人。一對的共同時間是兩人停留時間中較短的那個。
- 控制台和個人檔案上的**一起觀看**卡片會連結到這個頁面，個人檔案的卡片還會說明那個人的觀看時間有多少比例是有人陪伴的。
- `GET /api/stats/groups` 新增 `pairs`、`series`、`people`、`previous`、`bucket`，總計中也新增 `watch_s` 和 `share`；原有的鍵維持不變。
- **大家在哪裡停下**，在每部電影和每一集的頁面上：每一分鐘仍在觀看的播放比例，從開頭的所有人到看到最後的人，並在同一條軸上標示這些播放中的倒轉和開啟字幕。卡片會說明有多少停止點是量測的（FinStats 記錄的播放），有多少是估計的（匯入的播放，依它們播放的時長），而且要有三次播放才會畫出任何內容。
- **誰繼續看下去**，在影集頁面上：依序列出有多少人開始看每一集，每一集還有**看完**欄。「大家都在第三集放棄」指的是從來沒有按下第四集播放的人。
- **從來播不起來的檔案**，在播放頁面上：開始了三次以上、卻從未超過三十秒的電影或單集，附上誰嘗試過、用了哪些應用程式。Jellyfin 的記錄中沒有播放錯誤，所以由播放本身作證；最短播放長度在這裡不適用，因為那正是這些播放從未達到的。
- **最常倒轉**和**開啟字幕**，在播放頁面上：依每次播放的倒退跳轉次數排名的作品，附上倒轉集中的那一分鐘；以及依前十分鐘內開啟字幕的播放比例排名的作品。這三份清單都需要 *查看所有人的活動*。短於 20 秒的跳轉從未被記錄，所以重聽一句台詞這種短暫倒轉，在設計上就看不到。
- 跳轉會在標籤旁以數字保留它的起點（播放時間軸中的 `from_s`）。已經記錄的每次跳轉都會從標籤取得這個數字，在此之前的備份還原後也一樣。
- `GET /api/stats/files` 提供這三份清單；`GET /api/items/{id}` 新增 `insights`，影集的單集新增 `users` 和 `finished`。
- **API 金鑰**：任何登入的人都可以在「設定 → API 金鑰」中為自己建立金鑰，供指令碼、儀表板或手機使用。金鑰以 `Authorization: Bearer fs_…` 傳送，只顯示一次，以雜湊儲存，可以設定到期日，按一下就能撤銷；管理員可以看到並撤銷每個人的金鑰。它代表同一個人、擁有與登入時相同的權限，每次請求時即時讀取，所以失去登入權限時，所有金鑰會同時失效。金鑰既不能建立也不能撤銷金鑰。
- **行事曆訂閱**：`GET /api/calendar.ics?key=…` 提供 Sonarr 和 Radarr 即將推出的內容，是手機可以訂閱的 iCalendar。具有 *行事曆* 範圍的金鑰只能開啟這個訂閱，不能做其他事；因為已訂閱的行事曆無法送出標頭，所以訂閱從網址讀取金鑰，絕不使用 cookie，而且不提任何人的名字。
- **稽核記錄**，位於「伺服器 → 稽核」，供 Jellyfin 管理員使用：每次登入和登入失敗及其位址、每項設定或權限的變更及變更後的值、每把金鑰的建立、使用或撤銷、每個連線、目的地、備份和匯入、每次刪除播放和解決警示，附上是誰、從哪裡、透過哪把金鑰，以及是否成功。保留一年，包含在備份中。可用 `GET /api/audit` 逐頁讀取。
- **從 Streamystats 匯入**，在設定中與 Jellystat 並列，有自己的分類。取得它的 **Settings → Backup & Import → Download Backup** 檔案並拖放進來：多年的記錄幾秒內就會匯入，你已經有的內容不會重複計算。`finstats import-streamystats <file>` 可在無介面的情況下執行，透過 API 則是 `POST /api/import/streamystats`；同一時間只執行一個匯入，不論哪一種。
- **兩個追蹤工具都用過？兩個檔案都匯入吧。** 判斷一次播放是否 FinStats 已經有了，先看追蹤工具自己給它的 ID，找不到時再看是否為同一個人觀看同一個項目，而且播放的任一端與記錄中某次播放的時間相近。所以同樣幾個晚上的 Jellystat 匯出檔和 Streamystats 匯出檔可以都匯入，順序不拘，FinStats 自己記錄的晚上也不會被匯入的資料覆蓋。「相近」的標準就是「設定 → 收集」中的合併時間範圍。
- 匯入的資料列只說它能說的。Streamystats 自己記錄的播放沒有保存檔案的任何資訊（沒有編解碼器、解析度、位元速率或容器），所以這些欄位會留空，而不是填入猜測，會顯示它們的卡片也會自行隱藏。它從 Jellystat 取得的播放則帶有完整的工作階段，所以改為讀取那些資料：以播放結束的時刻為日期，這是兩個追蹤工具唯一都保留的時刻，而且只有在工作階段確實是轉碼時才標記為轉碼。
- Streamystats 因為 Jellyfin 回報某個項目已觀看而寫入的資料列，對應的是它從未看到的觀看，這些會被計數並略過：它們的長度等於整部電影，會變成某個沒人觀看的晚上的觀看時間。結果中會說明有幾筆。
- Streamystats 的資料如何逐欄解讀，是從真實的匯出檔而不是從文件學來的：`docs/streamystats-import.md`。
- **每次播放來自哪個追蹤工具**，成為活動上的篩選條件：FinStats 自己記錄的、來自 Jellystat 的、來自 Streamystats 的。只會提供你的記錄中實際存在的選項，而且它的範圍與其他清單相同，所以只能看自己播放的人，也只會知道自己的記錄來自哪裡。
- **活動上的篩選條件改為可勾選的下拉選單**，所以你可以要求電影*和*單集但不要音樂、兩種播放方式，或同時看兩個人，而不是每樣只能選一個或全選。媒體類型新增了**其他**，因為現在可以組合了。
- 在所有出現使用者篩選的地方（控制台、播放、媒體庫、安全性等），都可以同時選多個人，地圖和每項統計也會跟著變。使用者篩選仍然只會縮小某人能看到的範圍：沒有 *查看所有人的活動* 時，請求會固定為呼叫者本人，不論網址指定了誰、指定了多少人。
- **淺色佈景主題**：和紙的紙張，配上墨色文字和朱紅色的強調色。在你選擇之前，FinStats 會依循裝置的淺色或深色設定。
- **登出旁的佈景主題按鈕**會在跟隨裝置、淺色和深色之間循環切換。選擇會保存在這個瀏覽器中，並在頁面繪製之前套用，所以絕不會閃現另一種佈景主題。
- **在 Jellyfin 中開啟**：每部電影、影集和每一集的頁面上都有一個按鈕，會在新分頁中開啟該作品在 Jellyfin 中的頁面。
- **給使用者的 Jellyfin 位址**，位於「設定 → Jellyfin」：這些按鈕指向的位址，用於 FinStats 連線用的位址不是瀏覽器能連到的情況。留空則使用 FinStats 連線用的位址；只有 Jellyfin 管理員可以設定。

### Changed
- **FinStats 搬家了**：`github.com/finstats/finstats`，映像檔則是 `ghcr.io/finstats/finstats`。請在你的 `docker run` 或 compose 檔案中變更映像檔名稱，才能繼續收到更新；資料資料夾維持原樣。
- **設定一次只在畫面上顯示一個分類。** 原本的頁面是排成一欄的十四張卡片，加上六百字的說明。現在每個分類都有自己的網址（`/settings/collection`），左側的清單可以在它們之間移動，在手機上則變成一排標籤。指向舊錨點的連結仍然有效。
- **每項設定占一列**：它是什麼、一行說明規則、右側的控制項。同一分類中的數字以底部的一個按鈕一起儲存；開關仍會自行儲存。狀態卡片（工作、對外連線、資料庫）和授權條款連結位於**系統**之下，兩個匯入工具則有自己的分類。
- **尋找設定**：用標題區的方塊（按 `/` 聚焦）以名稱中的任何字詞搜尋；它會說明設定位於哪個分類，按 Enter 就會跳到那一列。
- **所有登入的人都能使用設定**：管理伺服器的分類仍只給可以管理的人，而只被允許接收通知的人，終於可以進入自己的目的地了。
- **伺服器頁面一次只在畫面上顯示一個分類**，與設定相同：總覽（系統和儲存空間）、工作、裝置、外掛程式、記錄和稽核，各有自己的網址。指向 `/server#jobs` 的連結仍然有效。
- **伺服器記錄成為伺服器頁面的一個分類**（`/server/log`），而不是選單中獨立的頁面；`/events` 會連同篩選條件轉到那裡。
- 關於工作失敗、備份失敗或連線停止回應的通知，會連結到存放它的設定分類，而不是頁面頂端。
- 你的媒體庫能告訴匯入播放的資訊（它是哪種東西、哪一集、它的片長、屬於哪個媒體庫），會在**每一次**媒體庫讀取後補上，而不只是在匯入的當下。記錄通常在 FinStats 讀取媒體庫之前就已匯入，所以那些播放以前會永遠停留在猜測或未知的狀態。
- 還原 FinStats 備份時，不會再新增以不同 ID 從追蹤工具匯入的播放，同時仍會保留相隔幾分鐘、確實是兩次的同一內容觀看。
- 播放的詳細資訊會指出是哪個追蹤工具帶進來的，而不是把所有匯入的播放都稱為 Jellystat 播放。

### Performance
- **不論記錄多大，重新啟動幾乎瞬間完成。** 以前每次啟動都會針對整份記錄算出誰和誰一起看，並重新判斷哪些播放是本地的，結果卻什麼都沒變：在一千萬次播放上分別要 24 秒和 5.5 秒。現在啟動只處理上次執行留下的部分，只有在更新之後或背後的設定變更時，才會全部重做。
- **一大群人同時開始播放，幾秒內就記錄完成。** 以前每次新的播放、每次進度儲存和每個裝置都是各自寫入，每次結束的播放也都各自查看該作品的完整記錄才關閉；現在每一輪會把同類的寫入一次完成。100,000 次播放同時開始只需 3 秒，以前 25,000 次播放同時結束要超過四分鐘。
- **數千人同時觀看時，正在播放依然快速。** 找出誰在一起看時，以前會把每個串流與其他每個串流比較，並列出每位同伴的名字：在 10,000 個串流時要四十秒，還要額外好幾 GB 的記憶體。現在只在同一部作品內比較串流，每個串流顯示幾個名字和其他人的人數。
- 以前每次 FinStats 啟動、匯入或看到播放結束時，計算誰一起看都會重寫整份記錄中每一筆已分組的播放；現在只寫入有變更的部分。找出哪些播放已經結束，也不再隨著正在播放數量的平方而變慢。
- **辨識記錄中已有的播放改為透過索引**，所以匯入 150,000 次播放只需幾秒，而媒體庫讀取後的重新連結也改為逐一走過作品，而不是在占住資料庫的情況下讀取每一次播放。
- **播放洞察和總覽在全部時間範圍上更快**：彼此獨立的部分會並行計算，同時串流圖表改為每十五分鐘查一次當地日期，而不是每次播放查一次，類型則改為依作品計算。在一百萬次播放上：從 4.1 秒降到 2.4 秒，以及從 1.6 秒降到 1.1 秒。

### Stability
- **電視節目的媒體庫不再被誤判為被清空的媒體庫。** 讀取媒體庫分成兩輪（每個項目，接著是只針對電影和影集演職人員的較小一輪），而判斷某次讀取能否被信任、用來移除它沒看到的項目的檢查，看的卻是第二輪。在電視節目或音樂媒體庫上，兩個數量相差甚遠，所以檢查拒絕了每一次讀取並停止 FinStats，安裝的系統重新啟動後又重複同樣的事。從來沒有東西被錯誤移除，但沒有任何媒體庫讀取能完成。如果你的影集或音樂媒體庫一直沒有收進新作品，原因就在這裡。
- 以前當另一個寫入（例如正在更新的播放）落在匯入的第一次讀取和第一次寫入之間時，匯入可能會以「database is locked」失敗。現在兩個匯入工具一開始就取得寫入鎖定，資料庫日誌也不再一直維持在史上最大一次匯入的大小。
- **損壞、被截斷、屬於別人或唯讀的資料庫檔案會立即被拒絕**，並指出是哪個檔案、說明沒有做任何變更，而不是沉默 30 秒；絕不會寫入其他程式的資料庫。
- 中途被打斷的備份或更新前快照不會再留下檔案，以前這種檔案可能在保留的三份中取代一份好的快照。
- **在 FinStats 執行中覆寫地點資料庫不會再讓它當機**：FinStats 改為讀取該檔案的私人副本。
- 每次都回報新裝置 ID 的 Jellyfin 應用程式，可能讓 FinStats 的記憶體在執行期間一直增長；現在五分鐘沒看到的裝置會被忘記。
- 每個人最多保留 30 個登入中的工作階段；下次登入時，最舊的會被登出。

### Fixed
- **項目重新命名後，同一個晚上不會再被計算兩次。** 把記錄重新連結到在 Jellyfin 中重新加入的作品時，從追蹤工具匯入的播放以前可能變成既有播放的重複，因為本來能抓到它的檢查是在 ID 移動之前執行的。現在只要重新連結 ID，就會再執行一次這項檢查。只有匯入的播放會被移除，絕不會移除 FinStats 自己記錄的播放，移除了多少會寫在記錄檔中。2.0 第一次啟動時，會把整份記錄掃過一次，清掉已經存在的重複。
- **工作階段現在會依循 Jellyfin 中這個人目前的狀態。** 被 Jellyfin 降級的管理員，以前在 30 天工作階段的剩餘期間仍保有 FinStats 的完整存取權，而在 Jellyfin 中被停用或刪除的人也仍然保持登入。現在只要 FinStats 讀取 Jellyfin 的使用者（每 15 分鐘一次，或從設定立即讀取），他們就會失去存取權，與 API 金鑰一向的做法相同。
- 登入時會把 Jellyfin 對這個人的說明寫入 FinStats 的使用者清單，所以匯入的追蹤工具備份，再也無法在第一次讀取使用者並修正之前，讓某人成為管理員。
- 即使兩次讀取使用者落在同一秒內，在 Jellyfin 中被刪除的人也會被標記為已移除。
- **下載錯誤絕不會顯示下載用戶端的密碼或索引器的 API 金鑰**，而 Sonarr 和 Radarr 可能會在錯誤中引用它們。
- 在媒體庫讀取期間被重新連結到重新命名作品的播放，以前要到下次重新啟動才會檢查是否為一起觀看；現在會立即檢查。

## [1.6.5] - 2026-09-24

### Added
- **每次升級前都會自動建立完整備份。** 較新版的 FinStats 第一次開啟你的資料庫時，會在變更任何東西*之前*，把它的完整副本（你的所有記錄、設定等）寫入 `data/pre-update-backups/`。萬一升級弄壞了什麼，你的資料仍然安全：停止 FinStats，用這份副本取代 `finstats.db`，啟動你原本使用的版本，然後回報這個錯誤。什麼都不會遺失。會保留最新的幾份副本；如果磁碟空間吃緊，設定 `FINSTATS_SKIP_PREUPDATE_BACKUP=1` 即可關閉。

## [1.6.4] - 2026-09-24

### Added
- **通知可以傳到另外五個地方**：Telegram、Slack、Pushover、Pushbullet 和電子郵件，加上原有的 webhook、Discord、ntfy 和 Gotify 目的地。每一種只要求它需要的資訊（聊天 ID、使用者金鑰、信箱），而只存在於單一服務的三種（Telegram、Pushover、Pushbullet）只能連到那個服務，所以權杖不可能被送到仿冒的主機。郵件從第一個位元組就透過 TLS 傳送，或使用 `STARTTLS`，沒有第三種選擇。

### Changed

- 同一時間只會執行其中一種：FinStats 在詢問時，會告訴 Jellyfin 停止傳送，並在最後一個播放結束的那一刻請它重新開始。連線自始至終保持開啟。

- 連線安靜時，設定中的**上次檢查**和對外連線卡片不會再過時：它們顯示的是 Jellyfin 對保持連線的回應。
